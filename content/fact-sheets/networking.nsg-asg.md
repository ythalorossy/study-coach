# Create and configure network security groups (NSGs) and application security groups

## Key concepts

- A network security group (NSG) filters traffic between Azure resources in a virtual network with rules that allow or deny inbound and outbound traffic, and it is attached to a subnet or to a network interface (NIC). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- To target one Azure resource, a rule uses its private IP address; inbound rules are evaluated after a public IP is translated to private, and outbound rules before private is translated to public. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- NSGs are stateful: an outbound allow on TCP port 80 automatically permits the inbound response, and an inbound allow permits the outbound reply, so reply rules are usually unnecessary. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- A rule matches the five-tuple of source, source port, destination, destination port, and protocol; rules run in priority order and evaluation stops at the first match, so later rules with the same attributes never run. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Azure's built-in rules sit at priority 65000-65500, the lowest priority, so custom rules are always evaluated first; built-ins can be overridden but not deleted or edited. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Inbound defaults: `AllowVNetInBound` (65000, `VirtualNetwork` to `VirtualNetwork`, allow), `AllowAzureLoadBalancerInBound` (65001, `AzureLoadBalancer` to all addresses, allow), and `DenyAllInbound` (65500, deny all). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Outbound defaults: `AllowVnetOutBound` (65000, `VirtualNetwork` to `VirtualNetwork`, allow), `AllowInternetOutBound` (65001, all sources to `Internet`, allow), and `DenyAllOutBound` (65500, deny all). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- `VirtualNetwork`, `AzureLoadBalancer`, and `Internet` are service tags, that is Azure-maintained IP prefix groups, while `0.0.0.0/0` means every address and is entered as `*` or **Any**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- An application security group (ASG) groups network interfaces so rules can target an application tier instead of explicit addresses, and one NIC can join several ASGs within Azure limits. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- Security admin rules from Azure Virtual Network Manager always outrank NSG rules: `Allow` continues into NSG evaluation, while `Always allow` and `Deny` stop it, delivering traffic straight to the resource or dropping it. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))

## Settings and limits

- Create an NSG in the portal via **Network security groups**, **+ Create**, then **Subscription**, **Resource group**, **Network security group name**, and **Region** on the **Basics** tab, then **Review + create** and **Create**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Create an ASG via **Application security groups**, **+ Create**, then **Subscription**, **Resource group**, **Name**, and **Region**; an ASG's location is fixed, but **move**, **Tags** **edit**, and **Access control (IAM)** are available. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Add rules with **+ Add** under **Inbound security rules** or **Outbound security rules**; **Source** offers **Any**, **IP Addresses**, **My IP address**, **Service Tag**, **Application security group**, and **Destination** offers the same list without **My IP address**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Each pick opens a matching field: **Source IP addresses/CIDR ranges**, **Source service tag**, **Source application security group**, **Destination IP addresses/CIDR ranges**, **Destination service tag**, **Destination application security group**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- The IP range fields accept a comma-separated list such as `10.0.0.0/16, 192.188.1.1`, and for an Azure VM you enter its private rather than public address. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- The ASG chosen for **Source application security group** or **Destination application security group** must exist in the same region as the network interface. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- **Source port ranges** and **Destination port ranges** accept one port like `80`, a range like `1024-65535`, a mix like `80, 1024-65535`, or `*` for every port. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- **Service** selects the destination protocol from a dropdown, either a predefined service such as **RDP** or **Custom**, where **Custom** requires **Destination port ranges**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- **Protocol** offers **Any**, **TCP**, **UDP**, **ICMP** and defaults to **Any**; `ESP` and `AH` are valid rule protocols only through ARM templates, not the portal. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- **Action** is **Allow** or **Deny**; **Priority** accepts 100 to 4096, must be unique within the NSG, and the lower number is evaluated first, so leave gaps like 100, 200, 300. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- **Name** is unique within the NSG, at most 80 characters, starts with a letter or number, ends with a letter, number, or underscore, and uses only letters, numbers, underscores, periods, or hyphens; **Description** is optional, up to 140 characters. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Augmented rules pack several explicit IP addresses or CIDR ranges and several ports into one rule, but a rule cannot mix multiple service tags or ASGs, and they exist only in NSGs built with the Resource Manager deployment model. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Azure caps NSGs per region and subscription, rules per NSG, and addresses or ports per rule; the numeric quotas are in the Azure subscription limits document these articles link to. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Managing NSGs, rules, and ASGs needs the Network Contributor role or a custom role; NSG work uses `Microsoft.Network/networkSecurityGroups/read`, `/write`, `/delete`, `/join/action`, and rule work uses `Microsoft.Network/networkSecurityGroups/securityRules/read`, `/write`, `/delete`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- ASG work uses `Microsoft.Network/applicationSecurityGroups/read`, `/write`, `/delete`, `/joinIpConfiguration/action`, `/joinNetworkSecurityRule/action`; an NSG `write` also needs `read` on the resource group, and a resource-group-only role can hide service tags unless `Microsoft.Network/locations/serviceTags/read` and `Microsoft.Network/locations/serviceTagDetails/read` are granted at subscription scope. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- Attach an NSG to a subnet with **Subnets**, **+ Associate**, then pick the virtual network and subnet and confirm with **OK**; detach with the three-dot menu, **Dissociate**, and **Yes**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))

## Compare and choose

- Prefer an ASG or a service tag over individual IP addresses in a rule. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- A rule naming an ASG affects only member NICs, so a NIC outside the ASG is untouched even when the same NSG is attached to its subnet. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- All NICs in an ASG must sit in one virtual network, and when a rule uses an ASG as both source and destination, all NICs in both ASGs must share that virtual network. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- Plan ASGs before writing rules so tier-to-tier traffic needs a few group references, and prefer service tags or ASGs over long IP lists to cut rule count and maintenance. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- To expose only a web tier, use `Internet` as source and the web ASG as destination with **Allow** on TCP port 80, like `Allow-HTTP-Inbound-Internet` at priority 100, because `DenyAllInbound` blocks unsolicited inbound traffic. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- To isolate a database tier, add a **Deny** rule for all sources to the database ASG on port 1433, like `Deny-Database-All` at priority 120, because `AllowVNetInBound` otherwise permits all same-virtual-network traffic. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- Give the legitimate path a lower priority number than that blanket deny, like `Allow-Database-BusinessLogic` at priority 110 from the logic ASG to the database ASG, so it matches first and everything else falls to the deny. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- The documentation example uses one NSG on two subnets and still narrows traffic by ASG membership. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/application-security-groups))
- To unblock traffic a built-in rule blocks, add a custom rule with a lower priority number instead of editing the built-in, and use security admin rules when policy must be enforced across subscriptions. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group)) ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))

## Gotchas

- Removing or changing a rule affects only new connections: an active SSH session survives deletion of the allow rule, while a new session is blocked. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Two rules cannot share a priority and direction, because that conflict makes traffic handling ambiguous, so keep every priority in an NSG unique. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Rule details, edit, and delete apply only to custom rules; built-in defaults cannot be opened, changed, or removed. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- An NSG cannot be deleted while it is attached to a subnet or NIC, and an ASG cannot be deleted while it still contains NICs. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/manage-network-security-group))
- The platform uses host addresses `168.63.129.16` and `169.254.169.254` for DHCP, DNS, IMDS, and health monitoring, and NSGs do not filter that traffic unless a rule targets `AzurePlatformDNS`, `AzurePlatformIMDS`, or `AzurePlatformLKM`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Windows licensing calls leave outbound on port `1688`, and that platform rule is disabled when the deployment uses the default route `0.0.0.0/0`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Behind a load balancer, the source address and port come from the originating computer and the destination address and port belong to the destination computer, not the load balancer. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- An NSG on a subnet hosting Azure PaaS resources such as HDInsight, Application Service Environments, or Virtual Machine Scale Sets can break the service when a required port is denied, so review port needs first. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- Send email through an authenticated SMTP relay, usually on TCP port `587`; direct outbound TCP port `25` is blocked for Pay-as-you-go, MSDN, Azure Pass, Azure in Open, Education, Free trial, and Cloud service provider subscriptions, and for Enterprise Dev/Test unless the **Can't send email (SMTP-Port 25)** diagnostic is run and the VMs restart. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
- NSG flow logs are retiring: new NSG flow logs can no longer be created, and on September 30, 2027 Azure deletes the existing NSG flow log resources and ends traffic analytics on them, so migrate to virtual network flow logs. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview))
