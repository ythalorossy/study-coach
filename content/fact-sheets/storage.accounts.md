# Create and configure storage accounts

## Key concepts

- A storage account is the single namespace for all Azure Storage data objects — blobs, files, queues and tables — reachable anywhere over HTTP or HTTPS. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- It is an Azure Resource Manager resource, so it must live in a resource group; at creation you create a new resource group or pick an existing one. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Recommended types are **Standard general-purpose v2**, **Premium block blobs**, **Premium file shares** and **Premium page blobs**; all deploy through ARM. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- **Standard general-purpose v2** supports blobs (including Data Lake Storage), queues, tables and Azure Files, and is the type Microsoft recommends for most scenarios. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- **Premium block blobs** covers block and append blobs for high transaction rates, small objects and consistently low latency; **Premium page blobs** covers page blobs only; **Premium file shares** covers Azure Files only. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Premium accounts use SSDs and offer only **LRS** or **ZRS** (page blobs only **LRS**); GPv2 offers **LRS**, **GRS**, **RA-GRS**, **ZRS**, **GZRS** and **RA-GZRS**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- In code, set the type with `kind` (`StorageV2`, `BlockBlobStorage`, `FileStorage`, `Storage` for legacy GPv1, `BlobStorage` for legacy Blob) and performance plus redundancy with `sku` or `SkuName` (for example `Standard_GRS`). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Legacy **Standard general-purpose v1** and legacy **Blob Storage** accounts can be upgraded in place to GPv2 with no downtime; classic (ASM) accounts were retired on 31 August 2024. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Every service gets its own standard endpoint built from the account name as subdomain: `https://<account>.blob.core.windows.net`, plus `.dfs.` (Data Lake Storage), `.file.`, `.queue.`, `.table.` and `.web.` under `core.windows.net`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- **Azure DNS zone endpoints** are a preview alternative where Azure picks the DNS zone at creation time, giving endpoints such as `https://<account>.z<N>.blob.storage.azure.net` with the zone id running from `z1`–`z9` or `z10`–`z50`; opt in via preview feature `PartitionedDnsPublicPreview`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- All data is encrypted server-side by default with Microsoft-managed keys, with no extra configuration. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Cost depends on region, account type, access tier, capacity used, redundancy, transactions and egress — an app reading your data from another region adds egress charges. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))

## Settings and limits

- **Storage account name**: 3–24 characters, lowercase letters and numbers only, unique across all of Azure. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Basics** tab: **Performance** defaults to **Standard** for general-purpose v2; **Premium** then requires choosing block blobs, file shares or page blobs. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- A geo-redundant choice (**GRS** or **GZRS**) replicates to a data centre in another region; ticking **Make read access to data available in the event of regional unavailability** produces the read-access variant (RA-GRS / RA-GZRS). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Preferred storage type** (Blob/ADLS Gen2, Azure Files, Tables, Queues) only steers the guidance in the creation experience; it never limits which services you can use in the account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Networking** tab: **Public network access** (enable inbound traffic, block all traffic, or secure with a network security perimeter), **Public network access scope** (all networks vs. selected virtual networks/IP ranges), and optional **Private endpoint**, which assigns a private IP from your virtual network. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Network routing** defaults to Microsoft network routing; the alternative sends traffic through the POP nearest the account, which can cut networking cost. **Internet protocol** can add IPv6 alongside IPv4, but IPv6 needs a public endpoint and is incompatible with private endpoints and internet routing. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Security** tab defaults: **Require secure transfer for REST API operations** on (HTTPS only), **Allow enabling anonymous access on individual containers** on, **Enable storage account key access** on, and **Minimum TLS version** at TLS 1.2, which rejects TLS 1.0 and TLS 1.1. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Default to Microsoft Entra authorization in the Azure portal** makes the portal use your Entra credentials for data operations, falling back to account keys only when Azure RBAC lacks the needed data permissions. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Permitted scope for copy operations** (preview) defaults to `From any storage account`; tighter values are `From storage accounts in the same Azure AD tenant` and `From storage accounts that have a private endpoint to the same virtual network`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Data protection** tab: **Enable point-in-time restore for containers**, soft delete for blobs, containers and file shares (minimum seven-day retention recommended), **Enable versioning for blobs**, **Enable blob change feed**, and **Enable version-level immutability support** for default time-based retention policies. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Point-in-time restore also switches on blob versioning, blob soft delete and the blob change feed, so budget for the extra cost. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Encryption** tab: **Encryption type**, **Enable support for customer-managed keys** (blobs and files by default; **All service types (blobs, files, tables, and queues)** extends coverage), **Encryption key** and a mandatory **User-assigned identity** when you choose customer-managed keys, plus optional **Enable infrastructure encryption** for double encryption. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Advanced** tab: **Enable hierarchical namespace**, **Enable SFTP**, **Enable network file system (NFS) v3**, **Allow cross-tenant replication** (on by default), **Access tier** (hot by default), **Enable Managed Identity for SMB**, **Require Encryption in Transit for SMB**. **Enable Defender for Storage** is on the **Security** tab, under **Microsoft Defender for Storage**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Scale defaults: capacity **5 PiB** per account, no limit on containers, blobs, directories, file shares, tables, queues, entities or messages. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Request rate is **40,000 requests per second** in listed high-throughput regions (such as **East US**, **West Europe**, **Australia East**, **South Africa North**, **USGov Virginia**) and **20,000 requests per second** elsewhere. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- GPv2/Blob bandwidth: ingress **60 Gbps** and egress **200 Gbps** in those regions, ingress **25 Gbps** and egress **50 Gbps** elsewhere; GPv1 allows 10 Gbps ingress everywhere. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Accounts per region per subscription: **250** standard endpoints by default, **1,000** with a quota increase, **5,000** with Azure DNS zone endpoints (preview), **5,250** combined by default and **6,000** with a quota increase. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Network rule limits per account: **400** IP address rules, **400** virtual network rules, **200** resource instance rules, **200** private endpoints. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Capacity, bandwidth and accounts-per-region quotas can all be raised by request through Azure Support. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))

## Compare and choose

- Use **Standard general-purpose v2** (`kind` = `StorageV2`) unless a workload forces otherwise; it covers the most scenarios. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Pick **Premium block blobs** (`kind` = `BlockBlobStorage`, `sku` = `Premium_LRS` / `Premium_ZRS`) for high transaction rates, small objects or strict low-latency block and append blob storage. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Pick **Premium file shares** (`kind` = `FileStorage`) for Azure Files needing both SMB and NFS; unlike premium block blobs, it doesn't support hierarchical namespace (nor do premium page blobs). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Hierarchical namespace (Data Lake Storage) works on **Standard general-purpose v2** and **Premium block blobs** only — not on premium file shares, premium page blobs or legacy types. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- NFS choice: enable **Enable network file system (NFS) v3** to let Linux clients mount a blob container, or use **Premium file shares** when SMB and NFS shares must coexist in one account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Redundancy choice: **LRS** cheapest, **ZRS** survives a zone failure, **GRS**/**RA-GRS** adds a secondary region, **GZRS**/**RA-GZRS** covers zone and region; zone-based options are limited by account type and region. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Recommended workload setup: a general-purpose v2 account with **ZRS or RA-GRS** and **soft delete enabled** for most workloads (the machine learning and AI row leaves it off), **Hot** access tier except backup and archive, which should use **Cool** (or **Cold** after a cost review). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Enable hierarchical namespace for analytics, HPC and ML/AI workloads; leave it off for cloud native and backup/archive workloads. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Encryption choice: Microsoft-managed keys for simplicity, customer-managed keys for control, and **Enable infrastructure encryption** when you need both service-level and infrastructure-level encryption. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))

## Gotchas

- You cannot change a storage account to a different type after creation; you must create a new account and copy the data. Moving to another region likewise means creating a copy of the account there and moving data with AzCopy or similar. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Not every region supports every account type or redundancy option, so check availability before picking **Region** on the **Basics** tab. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Allow enabling anonymous access on individual containers** is on by default, but it only lets someone turn anonymous access on for a container — no blob becomes public until that extra step is taken. Microsoft recommends disabling the account-level setting. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Require secure transfer for REST API operations** normally covers HTTPS, SMB and NFS; if **Require Encryption in Transit for SMB** is selected on the **Advanced** tab, that setting governs Files traffic and require-secure-transfer applies only to REST/HTTPS. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Clearing **Require secure transfer** is the only way to serve clients needing unencrypted SMB such as SMB 2.1, which weakens the account's security posture. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Disabling **Enable storage account key access** blocks Shared Key authorization, so any client still using account keys stops working and Microsoft Entra ID becomes the only option. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Customer-managed keys cover blobs and files only unless you choose **All service types (blobs, files, tables, and queues)**, and configuring them at creation requires a user-assigned identity to reach the key vault. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- **Allow cross-tenant replication** is enabled by default, so object replication across Microsoft Entra tenants stays possible until you deselect it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
- Azure DNS zone endpoints are preview-only, unavailable in government cloud regions, and retiring in **March 2027**; code may need the `get properties` operation at runtime to discover endpoints, so standard endpoints are safer. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Never cache the IP behind a storage endpoint: the endpoint is stable but its CNAME chain and A record change without notice, and the DNS TTL must be honoured. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-overview))
- Deleting a storage account deletes all data, recovery is only sometimes possible and never guaranteed, and deleting while a VM uses the account can fail with an "in use" error. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-create))
