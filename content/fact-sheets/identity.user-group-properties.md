# Manage user and group properties

## Key concepts

- The user profile is the directory record of a person's identity, and its values are what show up in Outlook, Teams, Windows and other apps. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Profile data sits in six categories: Identity, Job information, Contact info, Parental controls, Settings (sign-in rights and usage location) and On-premises (extra values for AD-synced accounts). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Edit under Entra ID > Users > All users > the account, then either **Edit properties** (full list on the All category) or the pencil icon per category on the **Properties** tab; both end with **Save**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Roles by task: User Administrator edits profiles, Guest Inviter invites external guests, Privileged Role Administrator assigns Entra roles, Global Administrator is needed for tenant-wide **User settings**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- A group is the unit that grants one set of access to many people, so permissions go on the group rather than on individuals. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Group creation and membership edits need at least **Groups Administrator** or **User Administrator**, plus an Azure subscription and tenant access. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Dynamic membership groups fill by rule: when any user or device attribute changes, every dynamic rule in the directory is re-evaluated and members are added or dropped. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Dynamic-group security equals the write access on the attributes its rule tests, so audit those permissions in Entra and in the source directory, especially on-premises attributes that allow SELF write. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- An agent's user account is a user subtype that user-based rules do evaluate and can include, so exclude it with a condition; agent identities (service principals) are never supported as members. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))

## Settings and limits

- **User settings** (Entra ID > Users > User settings, Global Administrator only) holds directory-wide switches: members registering their own applications, stopping non-admin members from creating their own tenants, letting members create security groups, guest access restrictions, limiting the admin portal, linking a work or school account to LinkedIn, the **Stay signed in?** prompt, and external collaboration options (guest access, guest invites, external user leave, collaboration restrictions). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Guest access restrictions has three levels: guests equal members (most inclusive), guests limited on directory object properties and memberships, or guests limited to their own objects (most restrictive). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Bulk edit on the **All users** page takes up to **60** selected users, started from the top bar **Edit** command or by right-clicking. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Only twelve attributes are bulk-editable — job title, department, employee type, employee hire date, city, state or province, country or region, street address, zip or postal code, office location, company name and usage location — and anything else must be done on that user's own profile. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- With on-premises AD as source of authority, identity, contact and job data must be changed in AD and land after the next sync; Entra-only attributes such as Usage Location can be edited in the portal, while User Principal Name, On Premises Immutable ID and Account Enabled are editable there but discouraged outside emergencies. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Parental controls: Minors (12 and under), Not adult (13–18), Adults (18 and over); age group combined with the parent-consent option yields a Legal age group classification that can limit access and authority. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Name guidance: first and last name should be the name the person wants shown, Display name carries your org's preferred order (e.g. `Green, Chris`), a middle initial such as `Chris B.` separates duplicates, and a legal name that differs from the preferred one stays in the HCM system. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Photos come from the camera icon on the thumbnail (initials show until then) and appear in Entra and on myapps.microsoft.com; upload failures usually mean the Office 365 Exchange Online Enterprise App isn't enabled. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
- Groups are created at Entra ID > Groups > All groups with **New group**; the Microsoft 365 type reveals a **Group email address** field that security groups don't have. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Group names must be unique and cannot start with a space, which would stop the group being offered as a role-assignment target. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Role-assignable groups require P1 or P2 licenses and at least **Privileged Role Administrator**; enabling that option automatically sets Membership type to **Assigned** and adds role steps to the creation flow. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Afterwards you can change group name, description and membership type, but **group type** is permanent (delete and recreate) and the **Object ID** is fixed, though copyable for PowerShell. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Only security groups nest, and nested groups help with membership and Conditional Access scopes without inheriting access to the parent's resources or apps. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Nesting is unsupported for AD-synced groups, security groups inside Microsoft 365 groups, Microsoft 365 groups inside security or Microsoft 365 groups, resource or app assignment or licensing on nested security groups, distribution groups in nesting, security groups inside mail-enabled security groups, and any group inside a role-assignable group. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- A group joins only one parent at a time, the **Select Group** box rejects wildcard characters, and removing it from a parent also strips the access its members inherited. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Everyone added to a new Microsoft 365 group gets a welcome notification whatever the membership type, including rule-driven additions; switch it off in Exchange PowerShell (`Set-UnifiedGroup`). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- With GDAP, a delegated administrator can't create a group when the target tenant's naming prefix or suffix is built from the calling user's attributes (department, company name); use an admin account in the target tenant instead. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- A tenant can hold at most **15,000** dynamic membership groups. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Licensing: one Microsoft Entra ID P1 or Intune for Education license per unique user in one or more dynamic groups (1,000 users needs 1,000 licenses), although they need not be assigned; devices in device-based groups need no license. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- The rule builder supports up to **five** expressions and user-based groups only; device groups and anything advanced — more than five expressions, direct reports rules, `-contains`/`-notContains`, explicit precedence, `(user.proxyAddresses -any (_ -startsWith "contoso"))` — need the text box. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- One expression is `<Property> <Operator> <Value>` with the property as `<object>.<property>`; parentheses are optional for a single expression and the rule body is capped at **3,072 characters**. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- User property types: Boolean (`accountEnabled`, `dirSyncEnabled`), date/time (`employeeHireDate`, preview, any `DateTimeOffset` or `system.now`), string, and string collection (`memberOf` preview, `otherMails`, `proxyAddresses`). ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Usable string properties include city, country, companyName, department, displayName, employeeId, givenName, jobTitle, mail, mailNickName, mobile, objectId, onPremisesDistinguishedName, onPremisesSecurityIdentifier, passwordPolicies, postalCode, preferredLanguage (ISO 639-1), state, streetAddress, surname, telephoneNumber, usageLocation (two-letter code) and userType (`member`, `guest`, `null`). ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Operators are `-eq -ne -startsWith -notStartsWith -endsWith -notEndsWith -contains -notContains -match -notMatch -in -notIn`; the leading hyphen is optional and `-contains` only does partial string matching, not collection items. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Precedence, highest to lowest: the comparison operators, then `-not`, `-and`, `-or`, and finally `-any -all`; parentheses are only needed when that default order isn't the intent. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Multi-value properties need `-any`/`-all`; `assignedPlans` exposes `capabilityStatus`, `service` and `servicePlanId` (Intune = `SCO`, Exchange Online (Plan 2) = `efb87545-963c-4e0d-99df-69c6916d9eb0`), and `_` matches any item in string collections. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Device rules can use deviceOSType, deviceOSVersion, deviceManufacturer, deviceModel, deviceOwnership, deviceTrustType, enrollmentProfileName, extensionAttribute1–15, isRooted, managementType, profileType, deviceId and devicePhysicalIds; extension attributes are `ExtensionAttribute1`–`ExtensionAttribute15` and only single-valued ones work, while custom directory properties use `user.extension_[GUID]_[Attribute]` and must come from apps in your tenant. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))

## Compare and choose

- Assigned vs dynamic: use **Assigned** when people are picked by hand and whenever the group is role-assignable; use **Dynamic** when membership should track attributes, accepting that members can't be added or removed manually. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Microsoft 365 group vs security group: Microsoft 365 groups accept users only and have an email address; security groups can hold users or devices and are what you nest and assign apps and resources to. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Intune assignment filters vs dynamic groups: filters target Intune apps and policies; dynamic groups serve non-Intune or cross-workload needs such as Conditional Access, licensing and Autopilot profile assignment. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Rule builder vs text box: the builder suits a few simple user expressions; anything advanced or device-based must be typed. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- `-any` vs `-all`: `-any` needs at least one matching item, `-all` needs every item — so `-all (... -eq null)` returns users with no service plans at all. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- All-users rule: `user.objectId -ne null` sweeps in members and business-to-business guests; add `-and (user.userType -eq "Member")` to keep members only. The device equivalent is `device.objectId -ne null`. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))

## Gotchas

- Switching on role assignability locks Membership type to **Assigned**, and membership type can't be changed after that. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- A wrong group type can't be edited away — the group has to be deleted and recreated. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Nesting is for scope, not access: the nested group gains no resources, apps or licenses, and it can only sit under one parent at a time. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Microsoft 365 group welcome emails don't care about membership type, so rule-driven additions still notify users. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Property names in rules are case-sensitive while regex and string matching aren't; escape embedded double quotes with a backtick and single quotes by doubling them. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- For null use only `-eq` or `-ne`; quoting `null` turns it into a literal string, and `-not` as the comparison operator raises an error. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Minimise `-match` and `-contains` in favour of `-startsWith`/`-endsWith` and `-any`, because partial-string matching slows dynamic group processing. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- `Direct Reports for "<manager objectID>"` also adds the manager, covers only direct reports, and cannot be combined with other rules. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- One rule can't mix users and devices, and a device rule can't reference the device owner's user attributes. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- `deviceOwnership` must be `Company` (Intune calls it `Corporate`), `systemLabels` is read-only, and the old `organizationalUnit` attribute is no longer recognised so it adds no devices. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Windows 10 needs `device.deviceOSVersion -startsWith "10.0.1"`; confirm the real value with `Get-MgDevice` first. ([Learn](https://learn.microsoft.com/en-us/entra/identity/users/groups-dynamic-membership))
- Using Display name as an alias makes a person render inconsistently across apps that read first/last name versus display name. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-user-profile-info))
