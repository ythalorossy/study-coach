# Configure and interpret reports and alerts for backups

## Key concepts

- Azure Backup reporting is delivered through **Azure Monitor logs** (Log Analytics) plus **Azure workbooks**, so every chart and grid in the report is driven by Kusto queries running against a Log Analytics workspace. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- The reporting pipeline has three parts: a Log Analytics workspace to hold the data, **Diagnostics settings** on each vault to ship data to it, and the Azure workbooks that render the reports. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- The Log Analytics workspace can live in a different location and subscription from the vaults that send it data. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Log Analytics retention defaults to 30 days, so raise the retention period if you need a longer reporting horizon. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- The **Backup Reports** report is a single consolidated view of jobs, instances, usage, policies, policy adherence and optimization; other reports are **Out-of-Box** views. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- The consolidated report supports Azure VM, SQL database in Azure VMs, SAP HANA in Azure VMs, MARS, MABS, DPM, Azure Files, Azure Disk, Azure Blob (operational tier) and PostgreSQL (Single Server). ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- **Backup Configuration Status** (Azure VM only) tells you which VMs are configured for backup; **Backup Job History** covers VM, MARS, MABS, DPM, PostgreSQL server, Azure Blobs and Azure Disks; **Backup Schedule and Retention** covers Azure VM and Azure Files; **User Triggered Operations** is scoped to the Recovery Services vault. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Azure Site Recovery contributes **Azure Site Recovery Job History** and **Azure Site Recovery Replication History**, but only jobs triggered on replicated items and recovery plans appear in the job history report. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Portal monitoring is available without any setup: the **Overview** pane of Resiliency, the Recovery Services vault and the Backup vault shows alerts, jobs, security and usage by default. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- Resiliency splits resources into **Protected Items** (resources covered by one or more solutions) and **Protectable resources** (resources not currently protected by any solution). ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- The **Backup Instances** section of a Recovery Services vault (or the **Backup instances** list in a Backup vault) lists each backup item of the workload type with its last backup status and latest available restore point. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- Azure Backup emits six diagnostic events: **Core Azure Backup Data**, **Addon Azure Backup Job Data**, **Addon Azure Backup Policy Data**, **Addon Azure Backup Storage Data**, **Addon Azure Backup Protected Instance Data** and **Azure Backup Operations**. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))

## Settings and limits

- To feed Log Analytics: open the vault, select **Diagnostics settings** > **+ Add diagnostic setting**, give it a **Diagnostics setting name**, tick **Send to Log Analytics**, choose the workspace, turn on **Resource specific**, select the six Azure Backup events, then **Save**. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- The **Resource specific** toggle only appears after you tick **Send to Log Analytics**; when you pick a storage account or event hub instead, you just tick the event checkboxes with no extra inputs. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Each event then lands in its own resource-specific table in the workspace, which you can query, join or union. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Recovery Services vaults can send diagnostic logs only to a storage account in the same region, but they can send them to a Log Analytics workspace in the same or a different region. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- For a Recovery Services vault, the six new events are honoured in Backup reports only in **Resource specific** mode; if you send them in **Azure diagnostics** mode, no data shows up in the reports. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- For a Backup vault, **Addon Azure Backup Storage Data** does not apply because storage consumed and frontend size already come through **Core Azure Backup Data** and **Addon Azure Backup Protected Instance Data**; selecting it would create a redundant table. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- The legacy **Azure Backup Reporting Data** event is supported only in **Azure diagnostics** mode; sending it in **Resource specific** mode flows no data. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Do not select **Addon Azure Backup Alerts**: the classic alerts solution is deprecated in favour of Azure Monitor-based alerts, and you should route fired alerts with an alert processing rule plus action group to a logic app, webhook or runbook. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- After configuring diagnostics, the initial data push can take up to 24 hours, and Microsoft recommends you start viewing the reports about two days after the change. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Reports never show the current partial day: with **Time Range** = **Last 7 days** you see the last seven completed days, and a custom range such as 23/3 4:30 PM – 24/3 10:00 AM is expanded internally to 23/3 12:00 AM UTC – 24/3 11:59 PM UTC. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- SQL log backup jobs are not displayed in Backup Reports. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Chart granularity depends on the range: 30 days or less renders daily, more than 30 and up to 90 days renders weekly, and anything larger renders monthly. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- In the Policy Adherence grids, items on a weekly policy have no daily view (weekly and monthly only), and a "month" there counts as 4 weeks (28 days) so partial weeks are excluded. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Widget load times grow with estate size and range: about 5,000 items over 1–3 months loads tiles, grids, charts and filters in 5–10 seconds; 10,000 items over 3 months takes 15–20 seconds for tiles and grids, 1–2 minutes for charts and 25–30 seconds for filters; 15,000 items over 3 months takes 20–30 seconds for tiles and grids, 2–3 minutes for charts and 50–60 seconds for filters. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- A built-in Azure Policy definition can add a diagnostics setting for every vault in a scope that has none or only a legacy setting; you can assign it to a whole subscription or a resource group and you need `Owner` access on each subscription. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- To find vaults still on the legacy event, run the documented Kusto query that unions `AzureDiagnostics` (filtering `Category == "AzureBackupReport"`, `OperationName == "Vault"`, `SchemaVersion_s == "V2"`) with `CoreAzureBackup` and returns vaults found only under `AzureBackupReport`. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- DPM-backed items only appear in the Recovery Services vault portal on DPM 1807 (5.1.378.0) or DPM 2019 (10.19.58.0 and above). ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- Backup item and protection group names for DPM, MABS and MARS cannot contain `<`, `>`, `%`, `&`, `:`, `\`, `?`, `/`, `#` or control characters. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))

## Compare and choose

- **Resource specific** mode (six new events) is the recommended target: it gives per-event tables, easier log queries, better schema discoverability and improved ingestion and query performance; **Azure diagnostics** mode with the legacy event is kept only for backward compatibility with existing custom queries and visualizations. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Keep two separate diagnostic settings while migrating — one for the legacy **Azure Backup Report** event in Azure diagnostics mode and one for the six new events in resource-specific mode — then retire the legacy setting. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Use the Log Analytics workbooks rather than the old Power BI template app, which sourced data from a storage account and is on a deprecation path; the **V1** schema for storage-account or Log Analytics destinations is also on a deprecation path in favour of the supported **V2** schema. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Choose the consolidated **Backup Reports** workbook when you need cross-workload visibility (usage, optimization, policy adherence); choose the out-of-box reports such as **Backup Job History** or **Backup Configuration Status** for a single-purpose view. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Choose a storage account when you want raw logs archived for custom analysis, an event hub when you need to stream to another system, and a Log Analytics workspace when you want the Azure Backup reports and workbooks. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Use Resiliency for a cross-solution estate view (**Protected Items** / **Protectable resources**) and the vault's **Backup Instances** / **Backup Jobs** blades for a single-vault, per-workload view. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- Prefer Azure Monitor-based alerts plus an alert processing rule and action group over the classic alert event when you need to notify on backup alerts. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))

## Gotchas

- Filters cascade left to right and top to bottom: a filter only affects widgets positioned to its right or below it, so a narrow filter placed at the top silently changes everything underneath it. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Only coloured tiles are clickable; clicking one (for example **Protection Stopped** on the **Backup Items** tab) filters the widgets below it, and uncoloured tiles cannot be selected. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Job details (except log jobs) appear based on when the job was *triggered* inside the selected range, not when it completed. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- **Cloud Storage** and **Protected Instances** values are snapshots taken at the *end* of the selected time range, not sums over the range. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Only backup items and policies that still exist at the end of the range are listed; items deleted midway through the range disappear from the report. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- Data shown is always full UTC days: on 29 March the reports contain data only up to 23:59 UTC on 28 March, and 29 March jobs appear on 30 March. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- A DPM data source whose protection was stopped but whose data is retained still shows in the portal, and if only online protection is stopped, billing for the online recovery points continues until the data is fully deleted. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-monitoring-built-in-monitor))
- Missing or partial report data is usually explained by three causes: vaults not sending the required diagnostic logs, wrong filters, or the reporting conventions above — check those before contacting Microsoft Support. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
- The Log Analytics reporting solution will stop supporting data from the legacy event, and the legacy event in Azure diagnostics mode is itself slated for deprecation, so migrate custom queries and automations to the new tables. ([Learn](https://learn.microsoft.com/en-us/azure/backup/backup-azure-diagnostic-events))
- Large estates with long time ranges can make the Kusto-backed widgets appear to hang; expect minutes rather than seconds for charts and report-level filters as item counts grow. ([Learn](https://learn.microsoft.com/en-us/azure/backup/configure-reports))
