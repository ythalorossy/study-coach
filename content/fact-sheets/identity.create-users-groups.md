# Create users and groups

## Key concepts

- A Microsoft Entra workforce tenant supports four user types: **Internal member** (typically your own employees), **Internal guest** (has an account in your tenant but only guest-level privileges, often pre-dating B2B collaboration), **External member** (authenticates with an external account yet gets member-level access, common in multitenant organizations), and **External guest** (signs in with an external method and holds guest-level privileges). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- A tenant in an *external* configuration is used only for Microsoft Entra External ID and contains **Internal user** (usually admins holding roles in the external tenant), **External user** (a consumer/business account for apps registered there, signing in with a local account or external IdP), and **External guest**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- Least-privilege roles differ by task: **User Administrator** to create a new user, **Guest Inviter** to invite an external guest, and **Privileged Role Administrator** to assign Microsoft Entra roles. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- Managing groups requires **User Administrator** or **Groups Administrator**, plus an Azure subscription and access to a Microsoft Entra tenant. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Only two group types are managed in the admin center: **Security groups** for access to shared resources (members may be users, devices, or service principals; they can be nested; owners may be users or service principals) and **Microsoft 365 groups** for collaboration (members must be users, though people outside the organization can join; owners may be users or service principals). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- The three membership types are **Assigned**, **Dynamic membership group for users**, and **Dynamic membership group for devices**; when a user or device attribute changes, the directory's dynamic membership rules are re-evaluated and the entity is added or removed to match. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- A dynamic group is built for users *or* for devices, never both, and device membership rules can only reference device attributes — so you cannot build a device group from device owners' attributes. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- Four ways to hand out access: **Direct assignment**, **Group assignment** (assign the group to the resource; every member gets access and both the group owner and resource owner can add or remove members), **Rule-based assignment** (a group whose membership is derived from user attributes), and **External authority assignment** (access flows from a source such as an on-premises directory or SaaS app). ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- Groups exist so permissions are granted once to a container instead of user by user, which supports the least-privilege principle and Zero Trust; groups can control access to Entra objects such as users, apps and billing, external SaaS apps, Azure services, SharePoint sites, and on-premises resources. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- Recommended practices include assigning at least **two owners** per group, enabling self-service group management with a naming policy and expiration policies, automating membership with dynamic groups (available for Microsoft 365 groups and Security groups), running periodic access reviews, using access packages, group-based licensing, sensitivity labels, and RBAC. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))

## Settings and limits

- The **Basics** tab of the new user form takes **User principal name** (unique username plus a domain chosen after the @, or **Domain not listed** to add a new domain), **Mail nickname** (uncheck **Derive from user principal name** to set a different nickname), **Display name**, **Password** (uncheck **Auto-generate password** to supply your own), and **Account enabled**, which is checked by default; unchecking it stops sign-in and was formerly called **Block sign in**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- The **Properties** tab has five categories: **Identity** (first/last name and **User type** set to Member or Guest), **Job information** (title, department, manager), **Contact information**, **Parental controls**, and **Settings** (global location). All can be changed after creation. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **Parental controls** age bands are **Minors** (12 and under), **Not adult** (13–18) and **Adults** (18 and over); the age group plus the parent-consent setting produces a legal age group classification that can restrict the user's access and authority. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- On the **Assignments** tab at creation time you can add up to **20 groups** and up to **20 roles**, but only **one administrative unit**; all three can be added later. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- For an external (Microsoft Entra External ID) tenant you use **New user** > **Create new external user**: set **Sign-in method** to **Email** and enter the address under **Value** instead of a UPN/mail nickname, add more addresses with **Add**, leave **User type** at its **Member** default, and note that **Authorization info** and employee/manager fields are unavailable and **Add administrative unit** and **Add role** are not offered. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **Invite external user** takes the guest's **Email** and **Display name**, plus an optional custom **Invitation message** enabled by the **Send invite message** checkbox (which also allows a Cc recipient); external users cannot be placed in an administrative unit. To make a guest with a domain account instead, use **Create new user** and set **User type** to **Guest**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- Invitation progress appears on the guest's details page in the **My Feed** > **B2B collaboration** tile; a state of **PendingAcceptance** lets you choose **Resend invitation**, and **Properties** shows the **Invitation state**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- Deleting a user requires at least **User Administrator**: a User Administrator can delete non-admin users, Helpdesk Administrators and other User Administrators, while **Privileged Authentication Administrator** can delete any user including other administrators. Deleted accounts remain listed under **Deleted users** for **30 days** and can be restored inside that window, and any licenses they held are freed up for others. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **New group** collects **Group type**, **Group name**, optional **Group email address** (offered only for Microsoft 365 groups, typed manually or built from the group name), optional **Group description**, the **Microsoft Entra roles can be assigned to the group** switch, **Membership type**, and optional **Owners** and **Members**. Names are checked for uniqueness and must not begin with a space. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Turning on **Microsoft Entra roles can be assigned to the group** requires **P1 or P2 licenses** and at least the **Privileged Role Administrator** role; enabling it automatically sets **Membership type** to **Assigned** and adds a role-assignment step to the creation flow. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- **Group type** is immutable — to change it you must delete the group and create a new one; **Object ID** cannot be edited but can be copied for PowerShell work, and once the role-assignable option is on you can no longer change the membership type. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- With nesting, a security group can be made a member of another security group only **one parent group at a time**, and wildcards are not accepted in the **Select Group** search box; adding members/owners or removing them, and editing name/description/membership type, all need **Groups Administrator** or **User Administrator**. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- A welcome notification is sent whenever users are added to a new **Microsoft 365** group, whatever the membership type, including when dynamic rules add members after an attribute change; you can switch this behavior off with Exchange PowerShell. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))

## Compare and choose

- **Member vs Guest**: member rights are the default for your own staff; choose Guest when the account should keep limited, guest-level privileges even though it lives in your tenant. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **Create new user vs Invite external user**: use **Create new user** for accounts whose credentials live in Entra ID (internal members and internal guests, or a guest using a domain account by setting User type to Guest); use **Invite external user** when the person brings their own email credentials and sets their own password from the invitation link. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **Create new external user** is the only path for a consumer/business account in a Microsoft Entra External ID tenant, whereas **Invite external user** applies to both workforce and external tenants but is still in preview for external tenants. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **External member vs External guest**: external members sign in to their home Entra tenant through a federated sign-in and an administrator in that home tenant resets their password; external guests set up their own password from the emailed link. Internal members and internal guests hold Entra-managed credentials and can reset their own password. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- **Security group vs Microsoft 365 group**: pick Security for resource access and when you need devices, service principals or nesting; pick Microsoft 365 for collaboration, for a shared mailbox-style email address, and when external people must join. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- **Assigned vs dynamic (users) vs dynamic (devices)**: choose Assigned for a hand-curated list, dynamic user groups for lifecycle driven by attributes such as department, location or job title, and dynamic device groups for device-driven collections. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- **Direct vs group vs rule-based vs external authority**: direct assignment suits one individual, group assignment removes per-user administration, rule-based assignment removes per-user administration and removes the risk of lingering access, and external authority assignment is right when membership is controlled by a directory or SaaS app. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- **Nesting is for scope, not for rights**: only members of the **parent** group gain access to resources and apps assigned to it, and nested groups don't pick up access held by the parent — so a child group can be used for membership and Conditional Access scopes but not as a way to inherit shared-resource permissions. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))

## Gotchas

- Nesting is not supported for groups synchronized from an on-premises directory, for adding security groups to Microsoft 365 groups, for adding Microsoft 365 groups to security or other Microsoft 365 groups, for assigning shared resources/apps to nested security groups, for licensing through nested security groups, for distribution lists in nesting, for adding security groups as members of mail-enabled security groups, or for adding a group to a role-assignable group. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- A group name that starts with a space makes the group unusable in steps such as choosing role assignments for group members. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Removing a nested security group from its parent also strips any access its members inherited from that parent. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Cross-tenant delegated administration (GDAP) admins can't create a group when the target tenant's naming policy prefixes or suffixes the name from calling-user attributes such as a person's department or organization; sign in with an admin account that belongs to the target tenant instead. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Some groups simply can't be touched from the Entra admin center or Azure portal: if it is synchronized from an on-premises directory you must work in that directory, while distribution lists and mail-enabled security groups are handled only through the Exchange admin center or the Microsoft 365 admin center. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
- For users whose source of authority is Windows Server Active Directory, identity, contact and job changes must be made in that directory and only appear in Entra after the next synchronization cycle. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-create-delete-users))
- Members and owners can be added from existing groups as well as individual users, so a group's members can themselves be groups — but only one administrative unit is supported per user at creation time. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/how-to-manage-groups))
- Group expiration policies delete unused groups automatically after a set period unless an owner renews them, which is the safety net for groups you create without dynamic rules. ([Learn](https://learn.microsoft.com/en-us/entra/fundamentals/concept-learn-about-groups))
