# Interpret an Azure Resource Manager template or a Bicep file

## Key concepts

- An ARM template is a JSON file that declaratively describes Azure infrastructure: the resources to deploy, their properties, and the resource group that holds them, without listing creation commands in order. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- A Bicep file describes the same infrastructure in a domain-specific language; the Bicep CLI converts it into an ARM JSON template at deployment, so no ARM capability is lost. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/overview))
- Both formats are idempotent: redeploying the same file leaves the same resource types in the same state, and a resource that already has the specified properties is not changed. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- Azure Resource Manager orchestrates the run: dependent resources are created in the right order, while resources with no dependency on each other are deployed in parallel. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- Deployment converts the template into REST API operations, and the **apiVersion** on a resource declaration is the API version used in the REST request to that resource provider. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- Resource Manager validates the template before deployment starts, and the what-if operation compares the file with the live environment to list resources to create, update, or delete plus property changes. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- A template spec stores a template as an Azure resource type with role-based access control, so readers can deploy it but not change it; deployment scripts add PowerShell or Bash, inline or external, to finish setup in one template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview))
- The ARM template sections are **parameters** for deployment-time input, **variables** for reused values, user-defined **functions**, **resources** for what is deployed, and **outputs** for returned values. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- A Bicep file may declare **param**, **var**, **resource**, **module**, **output**, **type**, **func**, **metadata**, and **targetScope** in any order, and each resource gets a symbolic name that you use to get values from the resource. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- Bicep adds concise syntax, type safety, IntelliSense and syntax validation in the VS Code Bicep extension, and immediate use of preview and GA resource types and API versions; Azure stores the deployment state. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/overview))

## Settings and limits

- **$schema** is required: use `2019-04-01/deploymentTemplate.json#` for resource group deployments in VS Code, `2015-01-01/deploymentTemplate.json#` for Visual Studio, `2018-05-01/subscriptionDeploymentTemplate.json#` for subscription scope, and the `2019-08-01` management group or tenant schemas for those scopes. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **contentVersion** is required and takes any value, such as `1.0.0.0`, to mark significant template changes; **resources** is required, while **languageVersion**, **apiProfile**, **definitions**, **parameters**, **variables**, **functions**, and **outputs** are optional. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **languageVersion** `2.0` adds symbolic names for resources, copy loops, and **dependsOn** arrays, symbolic names in **reference**, the **references** function, an **existing** resource property, user-defined types, and extra validation; **resources** becomes an object. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **apiProfile** names one profile that maps many resource types to their API versions, so a per-resource **apiVersion** can be left out; it helps when one template must run in global Azure and Azure Stack. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **definitions** holds user-defined type schemas and requires **languageVersion** `2.0`; a definition can set **type**, **allowedValues**, numeric and length bounds, **prefixItems**, **items**, **properties**, **additionalProperties**, **discriminator**, and **nullable**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Limits per template are 256 **parameters**, 256 **variables**, 800 **resources**, and 64 **outputs**; grouping several values into one object parameter lowers the parameter count. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Allowed **type** values are **string**, **securestring**, **int**, **bool**, **object**, **secureObject**, and **array**; **minValue** and **maxValue** bound integers inclusively, and **minLength** and **maxLength** bound strings, secure strings, and arrays inclusively. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **allowedValues** restricts input to a fixed list, **defaultValue** applies when no value is supplied, and parameter **metadata** with a **description** shows as a tip in the Azure portal. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Resource declaration properties are **condition**, **type**, **apiVersion**, **name**, **comments**, **location**, **dependsOn**, **tags**, **identity**, **sku**, **kind**, **scope**, **copy**, **plan**, **properties**, and nested child **resources**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **condition** is a boolean where `true` provisions the resource and `false` skips it; **location** is required by most resource types but not all, for example role assignments. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **copy** repeats resources or properties, its default **mode** is parallel, **mode** `serial` deploys instances one at a time, and **batchSize** sets how many run per serial batch. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- **scope** applies only to extension resource types and can target a scope other than the deployment scope; **identity** sits at the root of the declaration and selects system-assigned or user-assigned identity. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- A nested child resource gets no automatic dependency on its parent, so declare one explicitly, and only child types allowed by the parent schema may be nested; **dependsOn** can name only resources defined in the same template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- An output needs a **type** plus either **value** or **copy**, never both; its **condition** defaults to `true`, and a **securestring** output is hidden from deployment history and cannot be read by another template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- ARM user-defined **functions** cannot access **variables**, cannot call other user-defined functions, and cannot use **reference**; their parameters cannot have default values, and **parameters** inside them sees only their own parameters. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Bicep **targetScope** accepts `resourceGroup` (the default), `subscription`, `managementGroup`, and `tenant`; set it for non-resource-group deployments, and a **module** can use a scope different from the rest of the file. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- Bicep decorators work on **param**, **var**, **resource**, **module**, **output**, **func**, and **type**: **allowed**, **batchSize**, **retryOn**, **description**, **discriminator**, **export**, **maxLength**, **maxValue**, **metadata**, **minLength**, **minValue**, **sealed**, and **secure**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- **allowed** is valid only on **param**, so in a **type** or **output** you restrict values with union syntax such as `'Standard_LRS' | 'Standard_GRS'`; **secure** keeps a string or object parameter out of deployment history and logs. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- **retryOn** retries a resource deployment for the listed error codes, with an optional retry count of at most 10 and exponential back-off. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- Bicep `for` loops repeat resources, modules, variables, properties, or outputs over an array, an object, or an integer index, and `if` on a resource or module makes its deployment conditional. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))

## Compare and choose

- Pick Bicep for new authoring when you want concise syntax, type checking, IntelliSense, and inferred dependencies; the page says Bicep doesn't lose the capabilities of a JSON template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/overview))
- For API versions, ARM JSON can use one **apiProfile**, while Bicep has no **apiProfile** concept and puts the version in each type string, for example `Microsoft.Storage/storageAccounts@2025-06-01`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- For dependencies, Bicep infers them when a resource symbolic name is used in another declaration; ARM JSON lists dependencies in **dependsOn**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/overview)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- For conditional deployment ARM JSON sets **condition** while Bicep appends `if (...)`; for repetition ARM JSON uses **copy** with **count** and **input**, while Bicep uses a `for` expression. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- For reuse, ARM templates can be linked or nested under a parent template while Bicep uses **module** declarations with a file path and **params**; module outputs are reachable through the module symbolic name, and tiers with separate lifecycles can go into separate resource groups. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/overview)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- For secrets, ARM JSON uses **securestring** or **secureObject** while Bicep uses the **secure** decorator; both keep values out of deployment history, and to reuse one secret keep it in Azure Key Vault and reference it from a parameter file. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- For child resources, ARM JSON nests them under the parent **resources** array or declares them separately, while Bicep nests them or declares them separately with a **parent** property pointing at the parent symbolic name. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))

## Gotchas

- Keep a resource **apiVersion** stable once it works: set the latest version for a new template and change it only when you need a later feature, because a new version can change template behavior. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Avoid a **languageVersion** ending in `-experimental` in production, because experimental behavior can change at any time. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- Under **languageVersion** `2.0`, **expressionEvaluationOptions** defaults to `inner` with `outer` blocked, the **deployment** function returns only a limited property set, the Deployments resource needs **apiVersion** `2020-09-01` or later in a symbolic-name deployment, and expressions no longer need double escaping. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- The parameter constraints **prefixItems**, **items**, **properties**, **additionalProperties**, **discriminator**, and **nullable** require **languageVersion** `2.0`, and Bicep user-defined types, user-defined functions, compile-time imports, and experimental features generate 2.0 code automatically. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- JSON comments need the JSON with comments (JSONC) file type in VS Code and Azure CLI 2.3.0 or later with `--handle-extended-json-format`; multi-line strings work only in Azure PowerShell and that CLI version, not in the portal, DevOps pipelines, or the REST API. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- A **metadata** object is ignored by Resource Manager and your JSON editor may flag it as invalid, and you cannot attach **metadata** to a user-defined function. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/syntax))
- The Bicep file-structure page lists a `func` statement and ARM docs treat Bicep user-defined functions as a 2.0-triggering feature, yet the Bicep known-limitations section says user-defined functions are unsupported except as an experimental feature. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- Bicep ignores spaces and tabs but is sensitive to newlines, so a resource declaration cannot be split with `if (...)` starting on the line after `=`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
- Microsoft Customer Support does not assist with problems caused by Bicep experimental features, and a Bicep feature works only once the matching ARM JSON language support reaches the target environment, so Azure Stack can lag global Azure. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/overview)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/file))
