# Configure soft delete for blobs and containers

## Key concepts

- Blob soft delete keeps a deleted or overwritten blob, its snapshots and versions (or a directory, on accounts with a hierarchical namespace) inside the service for a retention period you choose, so it can be brought back to its state at deletion; once that period passes, the data is gone for good. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Blob recovery happens with the `Undelete Blob` operation while retention is still running, and the restored object comes back with its soft-deleted snapshots and versions; you cannot read data inside a soft-deleted blob or snapshot before restoring it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Container soft delete keeps a deleted container and everything inside it in the account for a retention period; the `Restore Container` operation brings back the container together with its blobs, blob versions and snapshots. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- The two features cover different scopes and Microsoft recommends enabling both, plus Azure Backup for wider risks such as accidental account deletion or ransomware; to roll them out across many accounts, assign the built-in policy **Configure soft delete for blobs and containers on storage accounts**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- A soft-deleted container is always restored as a whole, to its original name only, and only back to the state it had when it was deleted; to recover one blob whose container is still alive, use blob soft delete or blob versioning instead. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Enabling soft delete costs nothing extra and the snapshots or versions the service creates automatically are not billed as transactions, but the retained data is billed at the same rate and same tier as active data until retention elapses, and each `Undelete Blob` call is billed as a write transaction. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Microsoft's guidance is a minimum retention of 7 days; start with a short period to see how it affects the bill, then extend it to match data volume and how long detection and response to a loss event can take. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Retention is only a safety net for deletions made after the feature is on: enabling container soft delete does not recover containers deleted earlier, and turning the feature off never speeds up existing soft-deleted objects, which still expire on their original schedule. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Container soft delete does not protect against deleting the storage account itself; to block that, place a lock on the storage account resource. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))

## Settings and limits

- Blob soft delete retention can be any value from 1 to 365 days, and container soft delete uses the same 1 to 365 day range but defaults to 7 days; both can be changed at any time on an existing account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- In the portal, go to the storage account, then **Data Protection** under **Data management**, then the **Recovery** section and select **Turn on soft delete for blobs**; on hierarchical namespace accounts the same checkbox reads **Enable soft delete for blobs**. Enter 1-365 days and save. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-enable))
- When you create a storage account in the portal, the soft delete toggle sits on the **Data protection** tab and blob soft delete is already on by default, so new accounts are protected without extra work. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-enable))
- You can turn the setting on or off at any time with four options: Azure built-in policy, the Azure portal, PowerShell or the Azure CLI. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-enable))
- Container soft delete is supported on general-purpose v2 and v1, block blob and blob storage accounts, and on storage accounts with a hierarchical namespace enabled for Azure Data Lake Storage. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- API support floors differ: blob soft delete needs Azure Storage REST API version `2017-07-29` or later, while container soft delete needs version `2019-12-12` or later. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- The least-privileged built-in role that can restore a soft-deleted container is **Storage Blob Data Contributor**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Container retention changes are not retroactive: the new value governs only containers deleted after the update, while already soft-deleted containers keep the period in effect at deletion; to give one of them a longer window, undelete it and delete it again. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Retention cannot be extended after the fact for an object: once the period elapses the object is permanently deleted, and there is no way to recover it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Soft-deleted blobs are billed at the same rate and stay in their original tier, and the period starts the moment the delete or overwrite happens. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Support for the feature can be affected if you have enabled Data Lake Storage Gen2, NFS 3.0 or SFTP on the account, so check the Blob Storage feature support table for those configurations. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))

## Compare and choose

- Pick blob soft delete when the risk is individual blobs, snapshots or versions being deleted or overwritten inside a live container; pick container soft delete when the risk is the container itself being deleted; Microsoft recommends enabling both because neither covers the other. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- On a flat-namespace account with soft delete only, every overwrite silently creates a soft-deleted snapshot of the prior state, so overwrite-heavy workloads (logs, checkpoints, temp files) pile up retained copies and cost; on a hierarchical namespace account soft delete protects deletes only and overwrites are not captured. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- With blob versioning also enabled, overwrites create a version instead of a soft-deleted snapshot, the new version is not deleted when soft-delete retention expires, and `Undelete Blob` restores all soft-deleted versions at once with no selective single-version restore; to promote a version you undelete first, then copy that version over the base blob. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Metadata and property writes are the gaps to know: `Set Blob Metadata` and `Set Blob Properties` are not protected by soft delete alone, although with versioning enabled a metadata write does generate a new version. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- `Put Page`, `Put Page from URL`, `Append Block` and `Append Block from URL` are unchanged by soft delete, so overwritten page blob data is lost; that is why undoing writes an Azure VM made to an unmanaged disk with `Put Page` is not a supported recovery scenario. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- `Set Blob Tier` moves only the base blob to the new tier and creates no soft-deleted snapshot and no new version; active or soft-deleted snapshots and versions stay in the original tier. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Blob and container retention periods are independent, so align them: if the blob retention is shorter, a restored container can come back with its blobs already permanently deleted. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Lifecycle management policy deletions also produce soft-deleted objects that stay recoverable and billable for the retention period, so add that window to your storage-growth calculations. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- If the account has the permanent delete feature, a caller with the right permissions can remove soft-deleted snapshots and versions before retention expires; disable permanent delete if you want the full retention period guaranteed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- On premium block blob accounts, soft-deleted snapshots do not count toward the per-blob limit of 100 snapshots. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))

## Gotchas

- Enabling soft delete on a flat-namespace account blocks the Data Lake Storage (DFS) endpoint: calls to `*.dfs.core.windows.net` fail with `EndpointUnsupportedAccountFeatures`, so point the workload at `*.blob.core.windows.net` or upgrade the account to a hierarchical namespace. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Enabling blob or container soft delete also blocks migrating that account to a hierarchical namespace (for example `Invoke-AzStorageAccountHierarchicalNamespaceUpgrade` or `az storage account hns-migration start`); disable soft delete, migrate, then re-enable it, or enable ADLS at account creation. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Listing behaviour changes: code that lists with an "all" flag (`BlobListingDetails.All` in legacy SDKs, `BlobStates.All` in the v12 `Azure.Storage.Blobs` SDK) starts returning soft-deleted blobs, which can break backup and restore logic; use `BlobStates.None` for active blobs only or `BlobStates.Versioned` for versions without soft-deleted ones. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- `Delete Container` is unaffected by blob soft delete, so blobs in a deleted container are unrecoverable unless container soft delete was enabled before the deletion; `Delete Storage Account` is unprotected by both. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Blobs removed by the ADLS-only `Set Blob Expiry` operation never become soft-deleted and cannot be undeleted, and expiry on an existing blob in a hierarchical namespace account does not soft-delete it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- You cannot delete a base blob while it still has snapshots; deleting the blob and its snapshots together marks both as soft-deleted, and deleting a single active snapshot soft-deletes just that snapshot. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- On hierarchical namespace accounts, deleting a directory soft-deletes it with everything inside, and the contents stay inaccessible until you undelete the directory; renaming the directory disconnects its soft-deleted blobs, so restore the original name first. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Restores cannot overwrite live names: if you delete `a.txt` and then upload a new `a.txt`, the soft-deleted one cannot be restored until the active blob or directory of that name is deleted or renamed; the same applies to reusing a container name. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- Writing with `Put Blob`, `Put Block List` or `Copy Blob` onto a soft-deleted blob of a different type permanently deletes all existing soft-deleted data for that blob; `Put Block` against a soft-deleted blob instead creates a new blob plus an automatic snapshot of the old state. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Calling `Undelete Blob` on a blob that is not itself soft-deleted still restores every soft-deleted snapshot attached to it, and does nothing at all if there are no snapshots and the blob is not deleted. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- Soft-deleted objects are hidden from normal listings: use **Show active and deleted blobs** in the container view or **Show deleted containers** in the Storage browser, or call `List Blobs` with `include=deleted` / `List Containers` with `include=deleted` (`BlobStates.Deleted` in the v12 SDK). On hierarchical namespace accounts you cannot enumerate soft-deleted containers at all and must know the exact original name. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
- The automatic snapshot the service takes on overwrite does not appear in Azure Monitor resource logs or Storage Analytics, so use an Azure Storage blob inventory report with `includeDeleted` set to `true` and aggregate `Content-Length`, because the **BlobCapacity** metric mixes soft-deleted and active data. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-blob-overview))
- To purge data that is already soft-deleted sooner, undelete the blobs, turn off blob soft delete, then delete them again; bulk container restore is not available in the portal, so script it with Azure PowerShell or the Azure CLI. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/soft-delete-container-overview))
