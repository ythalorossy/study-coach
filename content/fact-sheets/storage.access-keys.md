# Manage access keys

## Key concepts

- Creating a storage account automatically generates two 512-bit account access keys. Either key can authorize access to all data through Shared Key authorization, or be used to sign a SAS token. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- A key is effectively a master password for the whole account: it grants full access to every blob, queue, table and file plus the power to mint SAS tokens, so it must never be hard-coded or kept in plain text. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Microsoft's preferred authorization model is Microsoft Entra ID with managed identities for blob, queue and table data, because it offers stronger security and easier management than Shared Key. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- When keys must be used, store them in Azure Key Vault and rotate them regularly; Key Vault allows rotation without interrupting applications. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- The two keys are named **key1** (the **primary** key) and **key2** (the **secondary** key); the same names are used in the portal, PowerShell and the CLI. Best practice is to use key1 in production and keep key2 in reserve for rotation. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Having exactly two keys is what makes a zero-downtime rotation possible: you move traffic to the secondary key, regenerate the primary, then move traffic back. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Reading keys requires being a Service Administrator or holding a role with `Microsoft.Storage/storageAccounts/listkeys/action`: **Owner**, **Contributor**, or **Storage Account Key Operator Service Role**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Rotating keys requires being a Service Administrator or holding a role with `Microsoft.Storage/storageAccounts/regeneratekey/action`, again **Owner**, **Contributor**, or **Storage Account Key Operator Service Role**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Blocking key-based authorization requires create/manage permission on the account, i.e. `Microsoft.Storage/storageAccounts/write` or `Microsoft.Storage/storageAccounts/*`, granted by **Owner**, **Contributor** or **Storage Account Contributor** at storage-account scope or higher. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Outside Azure, managed identities are still available through Azure Arc-enabled servers; for files, Azure Files over SMB should use Kerberos while REST can use SAS tokens. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))

## Settings and limits

- The `AllowSharedKeyAccess` storage-account property has no default and returns no value until you set it explicitly; **null** or **true** both mean Shared Key requests are still accepted. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Setting `AllowSharedKeyAccess` to **false** makes Azure Storage reject every subsequent key-authorized request; only requests authorized with Microsoft Entra ID succeed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Portal path to disable it: **Settings** > **Configuration**, then set **Allow storage account key access** to **Disabled**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- After the change, any Shared Key request fails with error code 403 (Forbidden), and the service reports that key-based authorization is not permitted on that account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Verify with `az storage account show --name <storage-account-name> --resource-group <resource-group-name> --query "allowSharedKeyAccess"`; the command outputs **false** only once Shared Key has actually been blocked. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- `AllowSharedKeyAccess` works only for storage accounts that use the Azure Resource Manager deployment model. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- To view keys: portal > storage account > **Security + networking** > **Access keys**, then **Show keys**; copy under **key1** from either **Key** or **Connection string**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- To regenerate in the portal: on the **Access keys** page choose **Regenerate** beside the primary key, update your connection strings, regenerate the secondary key the same way, then reload the page and confirm the value changed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Rotation reminder: **Set rotation reminder** > tick **Enable key rotation reminders** > choose a frequency > **Save**; the button stays greyed out until you have rotated each key at least once. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Compliance for rotation is monitored with the built-in policy **Storage account keys should not be expired**, assigned per scope and reviewed via **View compliance**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- The built-in policy **Storage accounts should prevent shared key access** blocks users with permission from creating or updating accounts that allow Shared Key; run it in **Audit** first, then edit the assignment's **Parameters**, uncheck **Only show parameters that need input or review** and switch the **Effect** from **Audit** to **Deny** (up to 30 minutes to take effect). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Bulk visibility: in the Azure Resource Graph Explorer, `resources | where type =~ 'Microsoft.Storage/storageAccounts' | extend allowSharedKeyAccess = parse_json(properties).allowSharedKeyAccess | project subscriptionId, resourceGroup, name, allowSharedKeyAccess` lists the setting for many accounts at once. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Count Shared Key traffic in **Monitoring** > **Metrics** with **Metric Namespace** *Account*, **Metric** *Transactions*, **Aggregation** *Sum*, plus **Add filter** on **Property** *Authentication*, operator `=`, values *Account Key* and *SAS*. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Identify the callers in Log Analytics after adding a diagnostic setting to the account, using `StorageBlobLogs | where AuthenticationType in ("AccountKey", "SAS") and TimeGenerated > ago(7d) | summarize count() by CallerIpAddress, UserAgentHeader, AccountName | top 10 by count_ desc`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))

## Compare and choose

- Entra ID vs Shared Key: Entra is Microsoft-recommended for OAuth-capable scenarios; Shared Key should be disabled when it isn't required so it can't be used by accident. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- SAS behavior once `AllowSharedKeyAccess` is **false**: user delegation SAS (Blob Storage only, Entra-authorized) is permitted, while service SAS and account SAS (both Shared Key-authorized) are denied on all services. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Rotation vs token revocation: regenerating keys invalidates account SAS and service SAS signed with that key, but user delegation SAS tokens survive because they are secured by Entra credentials. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Key Vault-managed rotation vs manual rotation: Key Vault swaps keys without app downtime, whereas manual rotation means editing connection strings in your code yourself. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Which key to use: Microsoft advises using only one key (key1) across all applications; mixing key1 and key2 makes rotation impossible without some application losing access. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Tool compatibility with Entra: Azure portal, Azure PowerShell, Azure CLI and Azure IoT Hub support it; AzCopy supports Blob Storage only; Storage Explorer covers Blob, Queue, Table and Data Lake but not File (pick the correct tenant). ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Cloud Shell caveat: it stores its persistent files in an Azure file share, so those files become unreachable if that account disallows Shared Key, and managing such accounts from Cloud Shell needs RBAC permissions. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Azure Files options before disabling: authorize file data with your Entra account in the portal, migrate the file data to a separate storage account, or simply don't apply the setting to accounts running Azure Files. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Use Microsoft Entra Conditional Access policies to protect a storage account only if Shared Key authorization is disallowed for that account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Logs that still show Shared Key after disabling mean trusted access is being used by resources registered in your Microsoft Entra tenant, not that the setting failed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))

## Gotchas

- Regenerating a key breaks every client that relied on it, including media services, cloud, desktop and mobile apps and GUI tools such as Azure Storage Explorer; each connection string must be updated. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-account-keys-manage))
- Azure Monitor metrics and logs do not separate SAS types: the **SAS** filter in Metrics Explorer and the **SAS** field in Storage logging report any SAS, so user delegation SAS traffic can be mistaken for Shared Key traffic. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- The Azure portal defaults to Shared Key for Azure file shares, so with the setting disabled and no matching RBAC assignments, file requests fail and shares can't be opened in the portal. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Many Azure services authenticate to Storage with Shared Key; disabling it silently removes their access and can stop working applications. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- **Owner**, **Contributor** and **Storage Account Contributor** grant no Entra data-plane access but include `Microsoft.Storage/storageAccounts/listkeys/action`, so assign them sparingly — assign least privilege only to those who must manage account properties. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Role assignments for changing `AllowSharedKeyAccess` must be scoped at the storage account level or above; classic Service Administrator and Co-Administrator count as ARM **Owner**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Disabling Shared Key does not block anonymous requests — if you configured anonymous read access on the account or container, those reads still succeed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Detection needs two tools: metrics give aggregate Shared Key/SAS counts, while per-client detail requires a diagnostic setting sending Storage resource logs to a Log Analytics workspace. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
- Migrate clients to Entra ID before blocking Shared Key, not after; to see why an account is non-compliant, check **Compliance reason** > **Details** on the assignment. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/shared-key-authorization-prevent))
