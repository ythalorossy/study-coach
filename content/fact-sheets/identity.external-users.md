# Manage external users

## Key concepts

- Microsoft Entra B2B collaboration (workforce tenants) lets a partner reach your apps and services with the credentials their own identity provider already issues — work, school or social accounts — so you never host, sync or expire an external account. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- After redemption (or after completing a self-service sign-up), the partner exists in your directory as a user object with user type Guest and a user principal name shaped as emailaddress#EXT#@<your tenant domain>, for example john_contoso.com#EXT#@fabrikam.onmicrosoft.com. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- B2B collaboration is enabled by default; administrators then control it with cross-tenant access settings (authentication against external Entra tenants) and external collaboration settings (who inside your org may send invitations). ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- The email one-time passcode is on by default for all new tenants and for existing tenants where nobody explicitly turned it off; if you switch it off, the fallback is prompting the invitee to create a Microsoft account. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Because of the guest sign-in experience update (rollout began July 2025, completed by end of 2025), a guest is redirected to their home organization's sign-in page, sees that tenant's branding and URL endpoint, and is returned to your tenant after authenticating. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Every B2B sign-in into a resource tenant produces a log in both tenants, carrying the application, email addresses, tenant name and tenant ID of the home and resource tenant. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- You can delegate onboarding by enabling self-service app and group management: nonadministrators use the Access Panel (myapps.microsoft.com) to add guest users to applications or groups, and application owners can add guests to any app they share. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Self-service sign-up user flows give guests a sign-up experience for your own apps, with social or enterprise identity providers, collected attributes, and API connectors for approval workflows or identity verification; the feature is enabled in external collaboration settings. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b)) ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Protection of shared content is separate from onboarding: Conditional Access policies such as MFA can target the tenant, one application, or specific guest users. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Turning on SharePoint and OneDrive integration for external sharing also turns on the email one-time passcode as those guests' fallback authentication method. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Custom onboarding can instead be programmed with the B2B collaboration invitation API (Microsoft Graph invitation resource) and governed with Microsoft Entra entitlement management access packages. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))

## Settings and limits

- Portal path for every external collaboration control: Microsoft Entra admin center > Entra ID > External Identities > External collaboration settings. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Guest user access is a three-way choice: the most inclusive option gives guests the same Entra resource and directory data access as members; the default option limits guests to properties and memberships of directory objects, blocking enumeration of users, groups and other directory resources while still letting them see membership of all non-hidden groups; the most restrictive option confines a guest to the properties and memberships of its own directory objects, hiding other users' profiles, groups and group memberships. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Guest invite settings is a four-way choice: everyone in the organization, guests and non-admins included (most inclusive); member users plus users holding chosen admin roles, including guests with member permissions; only users holding chosen admin roles; or nobody at all, admins included (most restrictive). ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- The admin roles that satisfy the admin-roles-only invite option are User Administrator and Guest Inviter. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Roles able to change external collaboration settings in the portal: Global Administrator or External Identity Provider Administrator; through Microsoft Graph, lesser-privileged roles may be able to change individual settings. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Self-service sign-up for guests via user flows is a Yes/No toggle — after setting Yes you still must attach a self-service sign-up user flow to each application. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- External user leave settings is Yes (guests leave on their own, with no admin or privacy contact approval) or No (guests see a message pointing them to the admin or privacy contact); the setting is unavailable until privacy information exists on the tenant. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Collaboration restrictions holds allow or block domain lists typed into text boxes, one domain per line, to allow or deny invitations. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Microsoft Graph resource types behind the controls: authorizationPolicy for guest user access restrictions and guest invite restrictions; authenticationFlowsPolicy for self-service sign-up via user flows; externalidentitiespolicy for external user leave settings; emailAuthenticationMethodConfiguration for the email one-time passcode, now on the All identity providers page of the admin center. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Guest Inviter is a directory role assignable to an individual (for example via New-MgDirectoryRoleMemberByRef with the role's ID) so they can invite guests without a higher-privileged administrator role; holders can invite even when invitations are restricted to specific admin roles. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Admin invitation flow: sign in as at least User Administrator, go to Microsoft Entra ID > Users > New user > Invite external user, enter email, display name and optionally a customized invitation message with Cc, then Review + invite — an invitation email is sent automatically and the account is created with user type Guest. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Wizard limits: a guest can be assigned up to 20 groups or up to 20 roles in one go, and assigning a Microsoft Entra role requires the Privileged Role Administrator role. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- An invitation does not expire and the guest account sits in the directory before redemption; check Entra ID > Users > the guest > My Feed > B2B collaboration tile, and when invitation state is "Pending acceptance" use Resend invitation. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Adding a guest to an existing group: Entra ID > Groups > All groups > the group > Manage > Members > Add members, then search by name or email address and Select; dynamic membership groups also work with B2B guests. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Adding a guest to an application: Entra ID > Enterprise apps > the app > Manage > Users and groups > Add user/group > the Users link > search > Select > Assign; the guest is listed with app role Default Access, changed via Edit > Select a role > Select > Assign. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Optional property categories in the wizard: Identity (first and last name, User type Member or Guest), Job information (job title, department, manager), Contact information, Parental controls (Minors are 12 and under, Not adult are 13-18, Adults are 18 and over, where age group plus parent-consent options produce the Legal age group that may limit access and authority), and Settings (global location). ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Your organization's privacy statement URL should be configured up front, because on first-time redemption the invited user must consent to the privacy terms to continue. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))

## Compare and choose

- Cross-tenant access settings govern whether your users can authenticate with another Microsoft Entra organization (inbound and outbound, scoped to specific users, groups and apps, and able to trust MFA, compliant and hybrid joined claims); external collaboration settings govern which of your users may send B2B invitations to guests of any organization. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- When both settings target the same partner, the most restrictive one applies: cross-tenant access enables collaboration with every Entra organization but adatum.com sits on the blocked-domains list, so your users cannot send invitations to adatum.com. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Blocking later is not retroactive: cross-tenant access allows Fabrikam and you then block fabrikam.com for invitations, so new Fabrikam guests cannot be invited while existing Fabrikam guests continue using B2B collaboration. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Out-of-the-box posture: B2B collaboration enabled, everyone including guests able to invite, and guest user access at the limited level rather than member parity. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b)) ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Match the invite option to the audience: open collaboration for anyone including guests; members plus selected admins; a controlled option where only User Administrator or Guest Inviter holders send invitations; or the lockdown option where nobody, admins included, can invite. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Match the role to the job: Global Administrator or External Identity Provider Administrator to change external collaboration settings; User Administrator to run invitations; Guest Inviter to delegate invitation-only rights; Privileged Role Administrator when directory roles are handed out during the invite. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Self-service sign-up via user flows fits app developers who want guests to sign themselves up and need API connectors for approvals and verification; the direct admin invitation with an invitation email or a direct app link fits individually onboarded partners. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Choose the creation path: Invite external user when you invite the guest by email address; use the create-new-user process with User type set to Guest when the guest needs a domain account from your own domain. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- After the guest is in the directory, you either send a direct link to a shared app or let the guest pick the redemption URL out of the invitation email. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- For cross-cloud partners — global cloud with Azure Government, or global cloud with Azure operated by 21Vianet — both tenants must enable each other in Microsoft cloud settings and then configure inbound and outbound cross-tenant access. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))

## Gotchas

- Email invitations address individuals only; group email addresses aren't supported. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Plus addressing breaks delivery — Entra doesn't currently support a "+" symbol plus text before the @, so omit the plus symbol and everything following it up to the @. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- The invited account is created with user type Guest before anyone redeems, and invitations never expire, so stale pending guests can linger in your directory and in group or app assignments. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Holding a limited administrator role isn't sufficient by itself: external collaboration settings must permit you to invite, and by default all users and admins can. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Restricting invitations to specific admin roles does not exclude Guest Inviter holders, whereas the most restrictive option stops even admins. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- The default limited guest access is not member parity: guests can't enumerate users, groups or other directory resources, but they do see membership of all non-hidden groups. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/external-collaboration-settings-configure))
- Assigning a guest to an app hands them the Default Access app role by default, so any different role requires editing the assignment afterwards. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
- Disabling the email one-time passcode removes the OTP path and leaves invitees being asked to create a Microsoft account. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Letting guests in and protecting them are two different jobs: authentication and authorization policies such as MFA apply at tenant, application or individual guest level. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/what-is-b2b))
- Mentioning in a group's description that it holds B2B guest users keeps members and admins clear about why external accounts appear in it. ([Learn](https://learn.microsoft.com/en-us/entra/external-id/add-users-administrator))
