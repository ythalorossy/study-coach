# Configure and interpret monitoring of virtual machines, storage accounts, and networks by using Azure Monitor Insights

## Key concepts

- VM insights performance tracks guest OS indicators for processor, memory, network adapter and disk utilization, so you can spot a failing component, tune the machine, and do capacity planning ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The performance experience described here is the logs-based one; a machine configured only with the metrics-based experience using OpenTelemetry metrics does not show these charts ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Storage insights merges performance, capacity and availability of Azure Storage accounts into one view, reachable either from a single account or across many accounts from Azure Monitor ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Storage insights requires no enabling or configuration because the account metrics it reads are collected by default, and using the feature itself is free - you pay only for Azure Monitor features you configure ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Network insights gives a configuration-free visual of topology, health and metrics for deployed networking resources, and exposes Connection monitor, NSG flow logs, VNet flow logs, Traffic analytics and Network Watcher tools ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Reading VM performance data requires the `Monitoring Reader` role on the virtual machine and on the VM insights data collection rule (DCR) ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Performance Diagnostics is the separate troubleshooting feature for Windows and Linux VMs and runs in two modes: **Continuous diagnostics** and **On-demand diagnostics** ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))

## Settings and limits

- The multi-VM performance view is reached with **Monitor** > **Solutions** > **Virtual Machines** > **Performance**, and covers VMs across work groups in your subscriptions ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- In that view the **Workspace** selector chooses the Log Analytics workspace that has the solution enabled (needed when several workspaces exist), while the **Group** selector filters by subscriptions, resource groups, computer groups and virtual machine scale sets ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Charts default to the last hour of data, and the **TimeRange** selector allows historical ranges of up to 30 days ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The **Top N Charts** tab shows five charts - **CPU Utilization %**, **Available Memory**, **Logical Disk Space Used %**, **Bytes Sent Rate**, **Bytes Receive Rate** - and each chart lists only its top five machines ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- **Aggregated Charts** defaults to average plus the 95th percentile for **CPU Utilization %** and **Logical Disk Space Used %**, while **Available Memory** defaults to average, 5th and 10th percentile, and the two byte-rate charts default to average only ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The percentile selector offers **Avg**, **Min**, **Max**, **50th**, **90th** and **95th** to change chart granularity inside the selected time range ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- **Top N List** starts with the 20 machines ranked by 95th-percentile **CPU Utilization %**; pressing **Load More** extends the list to 500 machines, which is the most that can be displayed at once ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- In **Top N List** the **Metric** dropdown switches the ranking to **Available Memory**, **Logical Disk Space Used %**, **Network Received Byte/s** or **Network Sent Byte/s**, and **Search by name** narrows to a single computer name ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The per-VM page (VM > **Monitoring** > **Insights** > **Performance**) adds **Logical Disk IOPS**, **Logical Disk MB/s** and **Max Logical Disk Used %** to the chart set, plus a table per logical disk showing capacity, utilization and average ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Scale sets are opened with **Virtual machine scale sets** > a VM > **Monitoring** > **Insights** > **Performance**, or per instance from the **Instances** view under **Settings** > **Instances** > **Insights** ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The pushpin icon pins a chart to the last Azure dashboard you viewed, and clicking the pinned chart reopens VM insights with the correct scope and view ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Linux limits: **Available Memory** is missing on some distributions such as RHEL 6, is present on kernel 3.14 or later, and may be present on kernels between 3.0 and 3.14 ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Disk metrics are only produced for data disks on Linux VMs using XFS or the EXT family (EXT2, EXT3, EXT4), and performance counters are not collected from network shared drives ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The storage **Overview** workbook pre-selects 5 accounts per subscription; choosing more in the scope selector returns up to 200 (573 accounts over three subscriptions would still show only 200) ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- The storage **Time Range** selector defaults to the last 4 hours, and the counter tile rolls up the total accounts in scope plus how many are selected ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Default availability health states are Warning at 99% and Critical at 90%; editing changes the **Critical** value of **Availability (%) (Thresholds + Formatted)** in the **Availability by API name** grid, so a minimum of 85 makes the state critical below 85% ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Customized workbooks can default to up to 10 subscriptions and up to 200 storage accounts, and are stored in a resource group under **My Reports** (private to you) or **Shared Reports** (visible to everyone with access to that resource group) ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Only three error types are broken out by default, such as **ServerOtherError**, **ClientOtherError** and **ClientThrottlingError**, with the remainder bucketed as **Other**; set `splitByLimit` to n+1 to surface n distinct error types ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- The multi-subscription and account-level **Overview** and **Capacity** workbooks can be exported to Excel with the down arrow next to the pushpin ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- The **Network health** tab filters on **Subscription**, **Resource Group** and **Type** and sorts by name or resource count; the search box also returns associated resources, so searching **agwpip** returns the public IP and its application gateway ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Some resource types are *onboarded*, which means they get a resource-specific topology view and a built-in metrics workbook; examples are **Azure Front Door**, **Application Gateway**, **Load Balancer** and **Traffic Manager** ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Other onboarded types protect and expose resources, for example **Azure Firewall**, **Azure Bastion**, **Network Security Group** and **Private Link** ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Connectivity and routing types are onboarded as well, including **Azure NAT Gateway**, **Network Interface**, **Public IP address**, **Route table / UDR**, **ExpressRoute**, **Local Network Gateway**, **Virtual Network Gateway**, **Virtual WAN**, **Virtual Hub** and **Virtual Network** ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))

## Compare and choose

- For a fleet-wide problem use the multi-VM **Performance** view under **Monitor** > **Solutions**; for one machine use that VM's **Insights** > **Performance**; for a scale set use the scale set **Insights** > **Performance** (or its **Instances** view for a single instance) ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- The VM **Performance** network chart and the Azure VM overview network chart are not the same data: the overview chart is measured by the host and shows only billable traffic, whereas VM insights is measured inside the guest and includes traffic between VMs ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- For storage, use **Monitor** > **Insights** > **Storage Accounts** to compare many accounts across subscriptions for availability, latency and errors; open one account > **Monitoring** > **Insights** for the per-account **Failures**, **Performance**, **Availability** and **Capacity** workbooks ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Match the storage workbook to the question: **Availability** for service health and per-data-service availability trend, **Performance** for E2E versus server latency and successful-call latency by API, **Failures** for client-throttling and other client errors by response type, **Capacity** for used capacity and object counts per data service ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Network insights is the read-and-visualize layer; when you must act, use its **Diagnostic Toolkit** (**next hop**, **IP flow verify**, **packet capture**, **connection troubleshoot**, **VPN troubleshoot**), the **Connectivity** tab for Connection monitor tests, and the **Traffic** tab for NSG flow log and Traffic analytics configuration ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Use **Top N Charts** for a quick five-machine ranking, **Top N List** to find which individual VM trends worst, and **Aggregated Charts** for averages and percentiles across many machines ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))

## Gotchas

- With several Log Analytics workspaces, picking the wrong one in **Workspace** leaves performance data empty, and the workspace/group choice applies to Performance only - it does not carry over to Map ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/vm/vminsights-performance))
- Availability thresholds work as a minimum/maximum pair, so the shipped configuration is minimum 90 and maximum 99 and critical is triggered only below the minimum value ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- A storage workbook is saved inside the storage account you were working in when you clicked **Save as**, so if you cannot find it, look in that account ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Customizations never overwrite the published default workbook: use **Save as** to create a copy, then **Done editing**, and launch your copy from the workbook gallery ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Heatmap colours differ by column type - error columns are shaded red, metric columns blue - with the deepest shade meaning the highest value ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-insights-overview))
- Network insights workbooks use the **Auto** time grain, derived from the selected time range; after pinning, the time range follows the dashboard settings instead ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- Changing Network insights requires **Edit Mode**, and the result is saved as a new workbook tied to a designated subscription and resource group ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- The **Traffic** tab lists NSGs across the selected subscriptions, resource groups and locations and flags which ones have **NSG flow logs** and **Traffic analytics** configured - you configure them from the **Flowlog Configuration Status** column ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
- **Connectivity** reachability status is driven by the criteria you set (checks failed % and RTT ms), so editing those thresholds immediately changes each test's reachability result ([Learn](https://learn.microsoft.com/en-us/azure/network-watcher/network-insights-overview))
