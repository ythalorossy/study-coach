# Move a virtual machine to another resource group, subscription, or region

## Key concepts

- A resource-group or subscription move re-associates the VM with a different Azure Resource Manager scope; it never shifts the region where the VM actually runs. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- The portal **Move** button offers **Move to a new resource group**, **Move to a new subscription**, and **Move to a new region**; the first two are ARM moves, the third routes to Azure Resource Mover. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Standard moves run through the portal, `az resource move`, `Move-AzResource`, the `moveResources` REST operation, or `ResourceManagementClient.resources.begin_move_resources` in Python. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Request top-level resources only: `Microsoft.Compute/virtualMachines` carries `Microsoft.Compute/virtualMachines/extensions` along, children cannot move alone, and links to separately managed resources can break afterwards. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Source and destination resource groups are locked during the move, blocking create, delete, and update (a VM cannot be resized), while running VMs keep serving traffic with no service downtime. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- A resource group itself cannot move to another subscription; move its resources into a target group instead and recreate group-level tags, role assignments, and policies there. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- A cross-subscription move is three steps: consolidate dependents into one group, move the resource plus dependents to the target subscription, then optionally redistribute them into separate groups there. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- In that move the VM and every dependent, such as managed disks, must sit in one resource group and travel in the same request. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Moving rewrites the resource ID, for example `/subscriptions/{subscriptionId}/resourceGroups/{resourceGroupName}/providers/{resourceProviderNamespace}/{resourceType}/{resourceName}`, so dashboards, scripts, and templates need updating. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))

## Settings and limits

- Required permissions: `Microsoft.Resources/subscriptions/resourceGroups/moveResources/action` on the source resource group and `Microsoft.Resources/subscriptions/resourceGroups/write` on the destination group. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Both subscriptions must be active and in the same Microsoft Entra ID tenant; compare with `az account show --subscription <subscription> --query tenantId` or `(Get-AzSubscription -SubscriptionName <subscription>).TenantId`, and reconcile mismatches by transferring billing ownership or associating the subscription with the tenant. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- The destination subscription needs the resource provider registered, or the move fails with an error that the subscription isn't registered for a resource type; register it with `az provider register --namespace <namespace>`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Destination subscription quota must cover the incoming resources. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- One request holds at most 800 resources; more is rejected immediately and smaller sets can still time out, so split large moves. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- A move may run up to four hours with both groups locked throughout (most finish sooner); it has two phases (resources relocate, then dependent providers are notified), and a provider failure in either can hold the lock the full time. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- When four hours elapse, Resource Manager unlocks both groups: successfully moved resources sit in the destination and failures remain in the source. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Azure Disk Encryption: the VM moves to another resource group only while deallocated, and a cross-subscription move needs encryption disabled first with `az vm encryption disable --resource-group <rg> --name <vm> --volume-type all`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- Marketplace-plan VMs cannot move across subscriptions; deprovision in the current subscription and redeploy in the target, cloning the OS disk or moving the original disk after deleting the source VM. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- That redeploy works only if the plan still exists: check with `az vm image list-skus --publisher <publisher> --offer <offer> --location <location>`, then accept terms with `az vm image terms accept --publisher <publisher> --offer <offer> --plan <plan>`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- Azure Backup VMs need the **Restore Point Collection** deleted first (it removes only instant recovery points, not vault data); stop backup protection temporarily, then reconfigure backup at the destination. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- With soft delete turned on, the move stays blocked while restore points are retained: switch that protection off, or let the 14-day retention window expire after the restore points are deleted. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- Backup artifacts sit in `AzureBackupRG_<VM location>_1` by default (for example `AzureBackupRG_westus2_1`) with collections named `AzureBackup_<VM name>_###########`; find them with `az resource list --resource-type Microsoft.Compute/restorePointCollections` and delete with `az resource delete --ids <collection-id>`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- Not supported: low-priority VMs and low-priority scale sets moved across resource groups or subscriptions; a VM in an availability set moved individually; and VMs using scheduled patching moved across either boundary. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- Also not supported: scale sets with a Standard SKU load balancer or Standard SKU public IP, and VMs in an existing virtual network moving to another subscription unless that network and its dependents also move. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))
- On Azure Stack Hub resources cannot be moved between groups at all. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Azure Resource Mover requires **Owner** on the source subscription: for the first source/destination pair it creates a system-assigned managed identity and gives it **Contributor** or **User Access Administrator** there, plus quota in the destination subscription and a target-region price check. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Before a region move the VMs must be running, every destination disk attached and initialized, and the guest OS updated with current trusted root certificates and a fresh certificate revocation list (CRL). ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Replication needs outbound access: allow the required URLs through a URL-based firewall proxy, and add NSG service-tag rules for outbound traffic. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- In the target configuration the VM size must not be smaller than the source; edit it from the **Destination configuration** column, and the target group is auto-named `<sourceRGName-targetRegion>` unless you choose one under **Edit**. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))

## Compare and choose

- The portal offers **Move to a new resource group** and **Move to a new subscription**; a cross-subscription move needs both subscriptions in the same Microsoft Entra tenant. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Choose **Move to a new region** for geographic relocation, regional feature access, governance, or capacity reasons, since a standard move cannot change region. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Dry-run with `az resource invoke-action --action validateMoveResources` or `Invoke-AzResourceAction -Action validateMoveResources`; every real move validates automatically anyway. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Execute with `az resource move --destination-group <rg> --ids <id1> <id2>` plus `--destination-subscription-id`, or `Move-AzResource -DestinationResourceGroupName <rg> -ResourceId <ids>` plus `DestinationSubscriptionId`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- REST moves POST to `https://management.azure.com/subscriptions/<source-subscription-id>/resourcegroups/<source-rg>/moveResources?api-version=<api-version>`; pre-checks use the `validateMoveResources?api-version=2019-05-10` endpoint. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- In REST validation, 202 means accepted but undecided; poll the `location` URL after the `retry-after` seconds, 204 confirms success, and failure returns `ResourceMoveProviderValidationFailed`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- For dependencies, **Show all dependencies** (default) lists direct and indirect ones such as NIC, virtual network, and NSGs, while **Show first-level dependencies only** shows only direct ones such as the NIC. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- **Discard move** returns resources to **Initiate move pending** for a trial, while **Commit move** finalizes the relocation and leaves sources in **Delete source pending**. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Resource Mover can change subscription and region in one attempt, though the tutorial flow moves within the source subscription first and switches subscription afterwards if preferred. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- For a Marketplace-plan VM pick redeployment; for an encrypted VM pick a deallocated resource-group move rather than a cross-subscription move. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-limitations/virtual-machines-move-limitations))

## Gotchas

- A read-only lock on the source group, destination group, or subscription blocks the move. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- Active role assignments do not travel with the resource; they are orphaned and then removed automatically, so recreate them after the move (removing them first is recommended). ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- `MissingMoveDependentResources` means a dependent was neither included nor already at the destination; a VM move can pull in seven resource types across `Microsoft.Compute`, `Microsoft.Network`, and `Microsoft.Storage`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- A virtual network gateway must stay in the same resource group as its virtual network because they cannot move separately. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- `MoveCannotProceedWithResourcesNotInSucceededState` often comes from a virtual network: if any direct or indirect dependent of a source or target network is not succeeded, the move is blocked even for an unmoved VM outside both groups. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- `RequestDisallowedByPolicy` means Azure Policy denied the move during validation, for example a rule blocking key vault creation in the target group. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- The source and destination groups cannot take part in another move simultaneously, so no conflicting moves to or from a third group. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/management/move-resource-group-and-subscription))
- A region move stops the source VM while a replica is built in the target region, usually a few minutes of downtime; other resources are recreated from generated ARM templates with usually no downtime. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- After committing, replication stops and the source VM and its networking are not further affected; the Azure Site Recovery Mobility agent stays installed, so uninstall it unless you plan another move, and adjust Azure RBAC rules afterwards. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Helper resources live in `RegionMoveRG-<sourceregion>-<target-region>`: move collection `movecollection-<sourceregion>-<target-region>`, cache storage `resmovecache<guid>`, vault `ResourceMove-<sourceregion>-<target-region>-GUID`; the collection is hidden by default and the cache storage has a lock to delete first. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
- Key vaults and SQL Server servers cannot be deleted from the portal after a region move; delete them from their resource property page. ([Learn](https://learn.microsoft.com/en-us/azure/resource-mover/tutorial-move-region-virtual-machines))
