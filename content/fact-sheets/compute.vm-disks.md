# Manage virtual machine disks

## Key concepts

- Managed disks are Azure-managed block storage volumes for VMs: you specify the disk type and size, and Azure provisions, replicates and manages the disk for you. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Azure offers five managed disk types: **Ultra Disks**, **Premium SSD v2**, **Premium SSD**, **Standard SSD** and **Standard HDD**, each aimed at a different workload. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- A VM has three disk roles: **OS disk** (one per VM, holds the boot volume and the OS you picked), **data disk** (application data) and **temporary disk** (local scratch space: `/dev/disk/azure/resource` on Linux, drive `D` on Windows). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Managed disks target 99.999% availability by keeping three replicas of your data; **LRS** gives at least 11 nines of annual durability, **ZRS** at least 12 nines. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Availability sets spread member VM disks across storage scale units (stamps) so one stamp failure doesn't break the set; availability zones protect against datacenter failures, with at least three zones per zone-enabled region. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Taking a snapshot of a managed disk yields an independent, read-only copy of that disk at one point in time; it is kept as a standard managed disk by default and survives changes to its source. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- A managed image is built from a deallocated, generalized (Sysprep) VM and packages every managed disk it had, OS and data, so one template can launch hundreds of VMs without you owning any storage account. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Encryption options: **Server-Side Encryption (SSE)**, **Azure Disk Encryption (ADE)**, **encryption at host** and **confidential disk encryption**, with platform-managed or customer-managed keys. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- One managed disk can be attached to several VMs at once for cluster apps, but that needs a cluster manager such as **WSFC** or **Pacemaker** for node communication and write locking. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Direct upload puts a VHD of up to 32 TiB into a managed disk without attaching it to a VM, avoiding the cost of an unattached disk. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Restrict imports and exports with a custom Azure RBAC role, **Microsoft Entra ID**, **Private Links**, **Azure Policy**, or the `NetworkAccessPolicy` parameter on the disk resource. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Scale limits per subscription per region: up to 50,000 disks of each disk type, and up to 1,000 VMs in a virtual machine scale set when the disks are managed. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))

## Settings and limits

- Ultra Disks: 4 GiB to 64 TiB in 1 GiB increments (max size 65,536 GiB), up to 400,000 IOPS and 10,000 MB/s, with 100 TiB allowed per region per subscription by default. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk performance: up to 1,000 IOPS per GiB, minimum baseline IOPS of 100, throughput of 0.25 MB/s per provisioned IOPS capped at 10,000 MB/s, minimum guaranteed throughput of 1 MB/s. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk capacity, throughput and IOPS are set separately and can be changed with the disk attached and the VM running: four resizes per 24-hour window, up to an hour to apply, and a resize can fail for lack of performance bandwidth capacity. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk limits: data disk only (never an OS disk, never Azure Compute Gallery), **LRS** only (no **ZRS**), no availability sets, no disk caching, 4k physical sector size by default with 512E optional. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD v2: 1 GiB to 64 TiB in 1 GiB increments (max 65,536 GiB), up to 80,000 IOPS and 2,000 MB/s, defaulting to 100 TiB per region per subscription (more by quota request). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD v2 baseline: 3,000 IOPS and 125 MB/s free on every disk; past 6 GiB IOPS rise 500 per GiB (80,000 IOPS needs at least 160 GiB) and throughput rises 0.25 MB/s per set IOPS (3,000 IOPS caps at 750 MB/s, 8,000 IOPS unlocks 2,000 MB/s). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD v2 has no fixed size tiers, no host caching, and four tuning operations per 24 hours, where creating the disk counts as one of them. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD v2 is data disk only and, in most zone-enabled regions, attaches only to zonal VMs — choose the zone when you create the VM. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD fixed sizes **P1**–**P80** (4 GiB to 32,767 GiB): base IOPS rises with size up to 20,000 at P80, and performance plus lifts P30, P40 and P50 to 8,000, 16,000 and 20,000, max 900 MB/s, usable as an OS disk, performance guaranteed 99.9% of the time at single-digit millisecond latency. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD bursting: **P30** and larger reach 30,000 IOPS / 1,000 MB/s with unlimited duration when on-demand bursting is enabled; **P1**–**P20** reach 3,500 IOPS / 170 MB/s for at most 30 minutes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Standard SSD sizes **E1**–**E80** (4 GiB to 32,767 GiB): base IOPS rises with size up to 6,000 at E80, and performance plus lifts E30, E40 and E50 to 1,500, 3,000 and 6,000, max 750 MB/s, allowed as an OS disk, available on all Azure VMs. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Standard HDD sizes **S4**–**S80** (32 GiB to 32,767 GiB): max 2,000 IOPS (500 base) and 500 MB/s, writes under 10 ms and reads under 20 ms, available in all regions on all VM sizes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- The OS disk holds at most 4,095 GiB, and a default **MBR** partition caps usable space at 2 TiB — beyond that use data disks or convert the OS disk to **GPT**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Temporary disks are encrypted automatically on Azure VM version 5 and above (such as **Dsv5** or **Dsv6**); otherwise enable encryption at host, or set `VolumeType` to `All` on Windows / `EncryptFormatAll` on Linux for ADE. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Billing rounds the provisioned size up to the next offered size (a 200 GiB Standard SSD bills as **E15**, 256 GiB) and prorates hourly; snapshots bill only for the data used (a 64 GiB disk holding 10 GiB bills 10 GiB). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Transaction accounting: on Premium SSD and Standard SSD each I/O up to 256 KiB counts as one operation, on Standard HDD each 16 KiB counts as one billable transaction, and both Standard tiers cap billable transactions per hour. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Enabling Ultra Disk capability on a VM adds a per-vCPU reservation fee even with no Ultra Disk attached (on **Standard_E32-8s_v3** the fee counts 32 cores); disk reservations discount one-year commitments on **P30**–**P80** Premium SSDs. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Portal attach: on the VM pane select **Disks**, then **Create and attach a new disk**, choose the SKU and size, name it and select **Save**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/attach-managed-disk-portal))
- In the guest run `diskmgmt.msc`, confirm the new uninitialized disk and select **OK**, right-click and choose **New simple volume**, finish the wizard, then select **Format disk**; the disk should end up **Online** and **Healthy** with a drive letter. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/attach-managed-disk-portal))

## Compare and choose

- Ultra Disks for SAP HANA, top-tier databases and transaction-heavy I/O; Premium SSD v2 for production workloads needing tunable performance (usually the best general-purpose price/performance); Premium SSD for fixed-size low-latency production; Standard SSD for web servers, lightly used apps and dev/test; Standard HDD for backup and infrequently accessed work. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk vs Premium SSD v2: Ultra has the higher ceiling (400,000 vs 80,000 IOPS, 10,000 vs 2,000 MB/s) but starts at 4 GiB and can never be an OS disk; Premium SSD v2 starts at 1 GiB, includes a free baseline and costs less for general use. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD vs Premium SSD v2: Premium SSD gives fixed **P** sizes with bundled IOPS/throughput, host caching, OS-disk support and reservations; Premium SSD v2 gives any size, per-IOPS and per-throughput control, no host caching and no OS-disk role. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Standard SSD vs Standard HDD: Standard SSD is lower-latency, more consistent and works as an OS disk; Standard HDD suits latency-tolerant sequential I/O, and the page says it isn't suitable for low-latency workloads such as OS disks or transactional databases, although it is still listed as usable as an OS disk until its retirement on Sept 8, 2028. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Managed image vs snapshot: an image comes from a deallocated generalized VM, carries all its disks and deploys many similar VMs; a snapshot copies one disk at a point in time for backup or a new disk, and doesn't coordinate across disks, so it won't suit striped sets. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Data disk vs OS disk: data disks improve backup and disaster recovery, give more flexibility and scalability, isolate performance, ease maintenance and tighten security and access control. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- **LRS** vs **ZRS**: **LRS** (11 nines) replicates within one datacenter and is the only redundancy Ultra Disks support; **ZRS** (12 nines) spans availability zones and is unavailable for Ultra Disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Managed disks vs **Azure Elastic SAN**: stay with managed disks for per-VM disks; consider Elastic SAN to consolidate many large-scale, I/O-intensive workloads and top-tier databases behind one back end, which can be more cost effective. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))

## Gotchas

- Ultra Disks and Premium SSD v2 can never be the OS disk — pair them with a Premium SSD or Standard SSD OS disk; Ultra Disks also can't be used with Azure Compute Gallery. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Using a Standard HDD as an OS disk is retired on **September 8, 2028**; migrate those disks before that date. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Initialize and format only a newly created, empty disk — doing it to a disk that holds data can make the data inaccessible or erase it permanently, so check the disk number, size and LUN first. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/attach-managed-disk-portal))
- Disks of 2 TiB or larger must use **GPT** partitioning; below 2 TiB you can choose **MBR** or **GPT**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/attach-managed-disk-portal))
- Temporary disk data can be lost during a maintenance event, when you redeploy a VM, and when you stop the VM; only a successful standard restart preserves it. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/managed-disks-overview))
- Ultra Disk target IOPS must stay below the VM's own IOPS limit or the disk can't deliver them, and a resize can fail simply because no performance bandwidth capacity is available. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Performance tuning is limited to four changes per 24 hours on Ultra Disks and Premium SSD v2; disk creation counts as one for Premium SSD v2, and each change can take up to an hour to take effect. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disks support no host caching, no **ZRS** and no availability sets, so high-availability and cluster designs must work around that. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk capacity is limited to 100 TiB per subscription per region by default — request a quota increase or contact Azure Support for more. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- In most availability-zone regions a Premium SSD v2 disk can only be attached to a zonal VM, so pick the zone at VM creation time; some regions allow nonzonal disks with extra limitations. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Ultra Disk and Premium SSD v2 default to a 4k physical sector size; apps needing 512-byte sectors need 512E, and Oracle Database before release 12.2 requires 512E, while Premium SSD and Standard SSD support the 512E sector size. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD burst is unlimited only on **P30** and above with on-demand bursting enabled; smaller sizes burst to 3,500 IOPS / 170 MB/s for max 30 minutes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
- Premium SSD v2 delivers its performance 99.9% of the time and Standard SSD only 99% of the time, with real IOPS and throughput varying by traffic pattern — size for the sustained target, not the peak. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-types))
