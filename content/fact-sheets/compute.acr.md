# Create and manage an Azure Container Registry

## Key concepts
- **Azure Container Registry** is a managed, private registry service based on the open-source Docker platform that builds, stores, and manages container images and related artifacts for use in development and deployment pipelines. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))
- A registry can hold Windows and Linux images: a **repository** groups related images, each image is an immutable copy of a container built for Docker, you choose the image names used across your deployments, standard Docker commands push and pull them, and related formats such as Helm charts and Open Container Initiative (OCI) images can live there too. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))
- Clients authenticate with an Azure identity, a **Microsoft Entra ID** service principal, or the registry's admin account over HTTPS/TLS, and Azure role-based access control (RBAC) then assigns specific registry permissions to users or systems. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))
- Basic, Standard, and Premium share the same programmatic capabilities and data-plane APIs, with storage managed by Azure and zone redundancy on by default in supported regions; every tier includes webhooks, **Microsoft Entra ID** authentication, and image deletion. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- **Azure Container Registry tasks** build images in Azure on demand or on triggers such as source-code commits and base-image updates, and multi-step tasks build, test, and patch images in parallel in the cloud. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))
- Images flow to orchestrators such as Kubernetes, DC/OS, and Docker Swarm, to Azure services including **Azure Kubernetes Service (AKS)**, **App Service**, **Batch**, and **Service Fabric**, and to CI/CD tools such as **Azure Pipelines** and **Jenkins**. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))
- Siting the registry in the same Azure location as its consumers reduces network hops, Premium geo-replication spreads one registry across geographies, and **Microsoft Defender for Cloud** can scan images whenever they are pushed. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-intro))

## Settings and limits
- Portal path: **Create a resource** > **Infrastructure services** > **Container Registry** > **Create**, then the **Basics** tab, where you pick a subscription and either an existing resource group or **Create new**. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Registry name** must be unique across Azure, contain 5-50 alphanumeric characters, and exclude `-`; it forms part of the registry's fully qualified DNS name. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Location** (West US 2 in the quickstart) and **Pricing plan** (Standard there) are chosen at creation, and the plan fixes the registry's features and limits. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Role assignment permissions mode** set to **RBAC Registry + ABAC Repository Permissions** keeps standard **Microsoft Entra ID** RBAC role assignments while optionally adding attribute-based conditions for repository-level access. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- The registry's **Login server** is the fully qualified address ending in `azurecr.io`; use that exact value in Dockerfiles, Kubernetes YAML, Helm charts, and Docker commands. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Domain Name Label (DNL)** prevents subdomain takeover by appending a unique hash to the DNS name, so protected registries resolve as `registryname-hash.azurecr.io`; the scope is permanent and downstream references must use the hashed name. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- DNL scopes: **Unsecure** (plain `name.azurecr.io`, no protection), **Tenant Reuse**, **Subscription Reuse**, **Resource Group Reuse**, and **No Reuse** (a new hash at every creation). ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- Sign in with `az acr login --name <registry-name>` or `Connect-AzContainerRegistry -Name <registry-name>`, passing only the resource name rather than the login server; success prints `Login Succeeded`. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- Publish with `docker pull mcr.microsoft.com/hello-world`, `docker tag` to `<login-server>/hello-world:v1`, then `docker push <login-server>/hello-world:v1` to create the `hello-world` repository and its `v1` tag; `docker run <login-server>/hello-world:v1` starts it, and `docker rmi` deletes only the local copy, while **Services** > **Repositories** > repository > **Tags** lists registry content. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- Included storage is part of the daily rate — the SKU table shows 1 GiB on Basic, 10 GiB on Standard, and 100 GiB and 500 GiB on Premium — extra use is billed per GiB up to the SKU limit, and anything beyond that needs Azure Support. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Maximum storage is 40 TiB on Basic, 40 TiB on Standard, and 100 TiB on Premium; maximum image layer size is 195 GiB and maximum manifest size 4 MiB in every SKU. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Webhooks are 2 on Basic, 10 on Standard, and 500 on Premium; private link with private endpoints is Premium-only with up to 200 private endpoints, and network controls are also Premium-only: 200 public IP network rules, 100 virtual network rules, and service endpoint VNet access in preview. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Repository-scoped permissions with **Microsoft Entra ID** role assignments work on all SKUs, as do non-**Microsoft Entra ID** tokens and scope maps: 100 tokens and 100 scope maps on Basic, 500 and 500 on Standard, 50,000 and 50,000 on Premium, with 500 actions per scope map and 2 repositories per scope map on Basic or 500 on Standard and Premium, which also caps each of `content/read`, `content/write`, `content/delete`, `metadata/read`, and `metadata/write`. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Anonymous pull access is N/A on Basic but supported on Standard and Premium; artifact cache rules behave the same way. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Premium-only capabilities: geo-replication, dedicated data endpoints, content trust, customer-managed keys, connected registries, artifact streaming, IP access rule configuration, retention policy for untagged manifests, artifact transfer, export policy, and dedicated agent pools for tasks. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Registry API rate limits are measured in requests per minute (r/m) and differ by SKU; exceeding one returns HTTP 429 Too Many Requests with a `Retry-After` header, enforced by a continuously refilling token bucket that tolerates bursts but can throttle for up to a minute. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Per-registry limits on Basic and Standard are 10,000 r/m DataplaneRead, 4,000 r/m MetadataRead, 500 r/m ListReferrers, 2,000 r/m DataplaneWrite, 1,000 r/m DataplaneDelete, and 10,000 r/m OAuth; Premium doubles them to 20,000, 8,000, 2,000, 4,000, 4,000, and 20,000. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Per-identity-per-registry limits on Basic and Standard are 5,000 r/m DataplaneRead, 2,000 r/m MetadataRead, 250 r/m ListReferrers, 1,000 r/m DataplaneWrite, and 500 r/m DataplaneDelete; Premium doubles them to 10,000, 4,000, 1,000, 2,000, and 2,000, and OAuth has no per-identity limit. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- MetadataRead and ListReferrers also consume DataplaneRead capacity, so a request is throttled if any limit it touches is exhausted; the admin account's `password` and `password2` share one identity bucket, and all anonymous requests share another. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Azure Support can raise storage limits, private endpoint counts, and push/pull performance limits (throttling, bandwidth, data-plane request rates); public IP network rules, service endpoint virtual network rules, non-Entra tokens, scope maps, actions per scope map, and repositories per scope map are fixed. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Published rate limits are best-effort approximations with no SLA, and `Retry-After` is recalculated on each 429 response so it counts down; honor the header and retry with exponential backoff and jitter. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Consumption appears on the registry's **Overview** page or via `az acr show-usage`, `Get-AzContainerRegistryUsage`, and the `Registries - List Usages` REST API, covering storage used, webhooks, geo-replications (home replica included), private endpoints, IP access rules, and virtual network rules; reported usage can lag recent operations, so check the `StorageUsed` metric, and a geo-replicated registry reports the home region only, so multiply by the replica count. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Change plan under **Settings** > **Properties** by editing **Pricing plan** and selecting **Save**, or run `az acr update --name myContainerRegistry --sku Premium` or `Update-AzContainerRegistry -ResourceGroupName myResourceGroup -Name myContainerRegistry -Sku Premium`; you can move freely between SKUs when the target plan can hold your data, with no downtime, but moving down from Premium disables Premium-only features and requires deleting geo-replications or connected registries first. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Pull and push speed depends on layer count and size, layer reuse, extra API calls per operation, concurrent deployment scale, Docker or Podman and containerd or CRI-O concurrency settings, cluster configuration, bandwidth, latency, firewall and proxy rules, and distance to the registry or nearest replica; diagnose with Azure Monitor by filtering **Transactions** on `ResponseType = Throttled`, splitting by `ApiName` and `Region`, and comparing **DataTransfer** by `ApiName` or `Region`, then mitigate with backoff and jitter, lower concurrency, staggered deployments, or a higher SKU. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))

## Compare and choose
- **Basic** is the cost-optimized tier for learning and low-usage development and testing; it keeps the shared features but has the smallest storage and image throughput allowances. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- **Standard** keeps the same capabilities as Basic with more included storage and throughput, satisfies many production workloads, and is the plan used in the portal quickstart. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Premium** adds the most included storage and concurrent operations, the highest API concurrency and bandwidth, geo-replication for one registry across regions, and private link with private endpoints for restricted access. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Choose **Premium** when content trust, customer-managed keys, connected registries, dedicated data endpoints, artifact streaming, IP access rules, untagged-manifest retention, artifact transfer, export policy, or dedicated task agent pools are required. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Choose **Standard** for anonymous pull or artifact cache rules without Premium cost, and **Basic** only for learning, development, and test; requirements for private endpoints, virtual network rules, or geo-replication rule out both. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Because every SKU shares the same data-plane APIs and Docker workflow, you can start on any plan and resize later without migrating image formats, as long as the target plan can hold your storage. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))

## Gotchas
- The DNL scope is fixed at creation, so a protected scope commits every Dockerfile, Kubernetes manifest, and Helm chart to the hashed `registryname-hash.azurecr.io` address. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- `az acr login` and `Connect-AzContainerRegistry` take the registry resource name only, while `docker tag` and `docker push` need the fully qualified login server. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- **Unsecure** DNL leaves the plain `name.azurecr.io` address with no takeover protection. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-get-started-portal))
- Basic has no anonymous pull access, private endpoints, public IP network rules, virtual network rules, service endpoint access, or geo-replication, so it cannot meet those requirements. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Rate limits are approximate targets rather than an SLA, and an exhausted token bucket can throttle requests for up to a full minute; `Retry-After` shrinks on each response, so use exponential backoff instead of a fixed sleep. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
- Before downgrading from Premium, delete geo-replications and connected registries; geo-replicated usage reports the home region only and can lag recent pushes, so track the `StorageUsed` metric near a limit. ([Learn](https://learn.microsoft.com/en-us/azure/container-registry/container-registry-skus))
