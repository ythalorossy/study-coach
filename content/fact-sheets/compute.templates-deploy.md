# Deploy resources by using an Azure Resource Manager template or a Bicep file

## Key concepts

- Azure Resource Manager (ARM) templates and Bicep files describe Azure infrastructure for deployment; Microsoft recommends Bicep because it offers ARM-template capabilities with easier syntax. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- A portal deployment started from the Marketplace still uses an ARM template behind the scenes; find that generated template later in deployment history. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- For a custom portal deployment, choose **Create a resource**, search for **template**, select **Template deployment**, then select **Create**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- The custom-template page offers **Build your own template in editor**, **Common templates**, and **Load a GitHub quickstart template**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- A loaded quickstart can be deployed unchanged with **Select template**, or changed with **Edit template** before selecting **Save** and **Purchase**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- The resource group's **Region** determines where its metadata is stored; Microsoft recommends the region used by most resources, and colocating can simplify a template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- Portal forms require **Subscription**, **Resource group**, and **Location**; **Create new** makes the group during deployment, and the user accepts **I agree to the terms and conditions stated above** before **Purchase**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- Portal parameter names are displayed in words: the camel-cased `storageAccountType` appears as **Storage Account Type**, while each template parameter can offer its default value. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- Deployment requires write access to the resources plus all operations on `Microsoft.Resources/deployments`; a virtual machine also needs `Microsoft.Compute/virtualMachines/write`, and what-if requires the same permissions. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Scope determines the command: resource group `az deployment group create`, subscription `az deployment sub create`, management group `az deployment mg create`, and tenant `az deployment tenant create`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Subscription, management-group, and tenant deployments require `--location`; the deployer also needs resource-creation rights at the selected scope. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- `--name` labels a deployment; without it, the file name becomes the name, so `azuredeploy.json` yields `azuredeploy` and `main.bicep` yields `main`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli)) ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- A template spec is a subscription resource containing an ARM template; Azure RBAC controls who can use it. The feature is currently in preview. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))

## Settings and limits

- The documented commands require Azure CLI `2.20.0` or later; deployment-command behavior changed in `2.2.0`. Azure CLI `2.76.0` or later and Azure PowerShell `13.4.0` or later add `ValidationLevel` for Bicep validation depth. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- A resource-group name can be at most `90` characters, may contain letters, digits, periods, underscores, hyphens, and parentheses, and cannot end in a period. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- `--template-file` points to a local Bicep file, `.json`, or `.jsonc`; `.jsonc` permits `//` comments, and the ARM service accepts those comments even when the extension is `.json`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- `--template-uri` deploys a remote ARM template, such as a publicly accessible GitHub URI; sensitive values belong in secure parameters rather than the template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- For a remote linked template with a relative path in storage, supply its SAS token with `--query-string $sasToken`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Azure CLI cannot deploy a remote `.bicep` file; build it to ARM JSON with the Bicep CLI, place that JSON remotely, and deploy the JSON. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Inline parameters accept strings, arrays, and objects; prefix a filename with `@` to inject its contents, and put double quotes around object JSON in Bash. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Array syntax differs by shell: Bash uses `'("value1", "value2")'`, while Command Prompt or PowerShell uses `"['value1','value2']"`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Parameter files can be `.json` or `.bicepparam`; Azure CLI requires a local parameter file and does not support an external one. Using `.bicepparam` requires Azure CLI `2.53.0` or later and Bicep CLI `0.22.6` or later. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- When a `.bicepparam` file has a `using` statement, omit `--template-file`; combining them causes an error stating that only a `.bicep` file may accompany a `.bicepparam` file. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Use a `.bicepparam` file only once in `--parameters`; inline values and a local JSON parameter file can also be supplied in the same operation. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- A parameter file containing `//` comments must end in `.jsonc`; with Azure CLI `2.3.0` or older, use `--handle-extended-json-format` for extended JSON. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Parameter evaluation is sequential: if a value is assigned more than once, the last assignment wins. Start with a parameter file, then override selected values with `KEY=VALUE`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- The default deployment mode is `Incremental`; select complete mode with `--mode Complete` in Azure CLI or `-Mode Complete` in Azure PowerShell. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- In either mode, Resource Manager creates template resources, takes no action on an existing resource whose settings are unchanged, and updates it when properties change. Changing an existing resource's location or type fails the deployment. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Incremental mode is not a partial property update: redeployment reapplies all properties, and properties omitted from the template reset to their defaults, so every non-default value must be stated. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Complete mode deletes resources that exist in the target resource group but are absent from the template. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Only root-level templates support `Complete`; linked or nested templates must use `Incremental`. Subscription-level deployments and the portal do not support `Complete`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Because `Complete` will gradually be deprecated, use deployment stacks when a Bicep or ARM template deployment must perform deletions. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Always run what-if before `Complete`; the preview identifies resources that will be created, deleted, or modified and helps prevent accidental deletion. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- If a conditional resource is skipped, deployment REST API versions before `2019-05-10` leave it in place, while `2019-05-10` or later deletes it; current Azure CLI and Azure PowerShell delete it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Resources omitted after a copy loop resolves are deleted in `Complete` mode. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- For a template covering multiple resource groups, `Complete` can delete only in the group named by the deployment operation; resources in secondary groups are not deleted. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Child deletion varies: omitting a parent DNS zone also removes its CNAME, but including the zone while omitting the CNAME leaves the CNAME. Some child resources aren't deleted when they're missing from the template, but they are deleted when their parent is. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- A locked resource group prevents `Complete` mode from deleting resources. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- For virtual networks, define subnets through the `Microsoft.Network/virtualNetworks` resource rather than the `Microsoft.Network/virtualNetworks/subnets` child, or redeployment can lose them. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- For web apps, an empty site-configuration object does not update `Microsoft.Web/sites/config`, but supplying new site-configuration values does update it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))

## Compare and choose

- Choose Bicep for easier authoring and ARM JSON when existing automation or tooling already expects the raw template format; both deploy through Azure Resource Manager. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Choose the portal for Marketplace or guided custom-template work; choose Azure CLI for scripted, repeatable deployments and for passing secure parameters that the portal cannot handle. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- With resources A, B, and C in a group and A, B, and D in a template, `Incremental` ends with A, B, C, and D, while `Complete` ends with A, B, and D because it removes C. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Choose deployment stacks rather than complete mode when template-driven deletion is required, because complete mode is being deprecated. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Choose a local file with `--template-file`, a remote ARM JSON file with `--template-uri`, or a template spec when the template must be shared under Azure RBAC control. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- Choose inline values for a small one-off change; choose a JSON parameter file for JSON values, or a `.bicepparam` file for a reusable Bicep parameter set that names its template with `using`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Choose `az deployment group create` for resources in one group, `az deployment sub create` for a subscription, `az deployment mg create` for a management group, or `az deployment tenant create` for the tenant. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))

## Gotchas

- Incremental mode still overwrites omitted properties with their defaults; the template always represents the resource's complete desired state, not just the changed fields. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- Reusing a deployment name replaces the earlier history entry; concurrent deployments with the same name let only the last finish, whereas sequential runs can create both resources but retain only one history entry. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Azure CLI cannot deploy a remote `.bicep` file directly; build it to ARM JSON first with the Bicep CLI. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- Combining a `.bicepparam` file with `--template-file` fails; use the `using` statement in the parameter file and omit that switch. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/deploy-cli))
- The portal cannot reference a secret from Key Vault; use Azure PowerShell or Azure CLI with a local or external-URI template for that scenario. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-portal))
- `Complete` can delete conditionally skipped resources, resources omitted after copy-loop expansion, and resources absent from the target group; check what-if before using it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
- The target resource group must already exist unless it is created separately; use `az group create --name ExampleGroup --location "Central US"` before a resource-group deployment. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deploy-cli))
- An existing resource cannot have its location or type changed by a deployment; create a new resource with the needed location or type instead. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/deployment-modes))
