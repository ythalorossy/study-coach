# Map an existing custom DNS name to an App Service

## Key concepts

- Mapping an existing custom DNS name means pointing a hostname you already own at an Azure App Service app, so that requests for that name are served by the app. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- The DNS record type is decided by the shape of the name: a root domain such as `contoso.com` uses an **A record**, while a subdomain such as `www.contoso.com` and a wildcard such as `*.contoso.com` use a **CNAME record**. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- An apex (root) name cannot use CNAME, which is why the root case is limited to an A record; RFC 1912, section 2.4 is cited as the reason. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Every custom domain in App Service needs two DNS records: the mapping record (A or CNAME) that routes traffic, and a **TXT** record carrying the domain verification ID. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- The domain verification ID in the TXT record proves ownership and is the main defense against subdomain takeover by another App Service app. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- An **App Service Managed Certificate** (ASMC) is the free, automatically renewed certificate that the **Add custom domain** dialog can request for you. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain)) ([Learn](https://learn.microsoft.com/en-us/azure/app-service/configure-ssl-certificate))
- Migrating a live site with no DNS downtime is done by preemptively binding the active DNS name to the App Service app before you touch the existing DNS records. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- A **deployment unit** (internally a webspace) limits how domains can move: one domain name can be assigned to only one app inside each deployment unit. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))

## Settings and limits

- Portal path: open the app's management page, pick **Custom domains** under **Settings** in the sidebar, then choose **Add custom domain**. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- **Domain provider** = **All other domain services** configures any third-party (non-Microsoft) domain; an App Service–purchased domain is handled by a different flow. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- **TLS/SSL certificate** offers **App Service Managed Certificate** when the app runs on Basic tier or higher, and **Add certificate later** when you must stay on the Shared tier or bring your own certificate. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- **TLS/SSL type** = **SNI SSL** allows many SNI bindings, so several certificates can secure several domains sharing one IP address. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- **TLS/SSL type** = **IP SSL** permits only one IP SSL binding per app, secures a dedicated public IP, needs DNS records remapped for IP-based SSL afterwards, and works only from Standard tier upward. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Other **Add custom domain** fields: **Custom domain** (the name the TLS/SSL binding covers), **Private Certificate Thumbprint** (which certificate to bind), **Domain** (the fully qualified name you own), **Hostname record type** (pre-filled with the recommended record for a root, subdomain or wildcard name), and **Validate**. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- The **Domain validation** section lists the two records you must create and offers copy buttons for each value. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Root-domain records: an **A** record with host `@` pointing to the app's IP address shown in the **Add custom domain** dialog, plus a **TXT** record with host `asuid` holding the domain verification ID that App Service reads to confirm ownership. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- TXT hosts used during a migration: root `\@` uses `_asuid_`, subdomain `www` uses `_asuid.www_`, and the wildcard `*` uses `_asuid_`; the value in each case is the ID from the **Custom Domain Verification ID** box. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Remap targets once the migration is validated: root domain = **A** record, host `@`, value = the app's external IP copied from the **Custom domains** pane; subdomain = **CNAME**, host `www`, value `<app-name>.azurewebsites.net`; wildcard = **CNAME**, host `*`, value `<app-name>.azurewebsites.net`. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- The **Custom Domain Verification ID** box on the app's **Custom domains** pane is where you copy the verification ID before creating the TXT record. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Tier limit: the app's **App Service plan** must be a paid tier; the Free (F1) tier cannot host a custom domain, so scale up first. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Zone limit: custom domains must live in a public DNS zone; private DNS zones are not supported. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- DNS access limit: you need rights to edit records in the domain provider's DNS registry (for example GoDaddy), and Azure DNS can be used to host those records instead. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Plan limit: on a Consumption plan, a function app accepts only the CNAME option, not an A record. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Deployment-unit facts: the unit shows up in the FTP/S hostname `<deployment-unit>.ftp.azurewebsites.windows.net`; it comes from the **App Service plan**, is chosen randomly when the plan is created, and cannot be changed afterwards. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Two apps created in the same resource group and the same region end up in the same deployment unit, so plan creation in a new resource group or region is the only way to land in a different unit. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Provider UI landmarks for record management: sections named **Domain Name**, **DNS** or **Name Server Management**, reached through links such as **My domains** and then **Zone file**, **DNS Records** or **Advanced configuration**. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))

## Compare and choose

- Root name: pick **A** record, because CNAME is invalid at the apex; subdomain and wildcard: pick **CNAME** record to the app's default hostname. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- For a subdomain you *could* point an **A** record straight at the app's IP, but a **CNAME** to `<app-name>.azurewebsites.net` survives an inbound IP change, so CNAME is the recommended option. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Certificate choice: **App Service Managed Certificate** gives you an auto-renewed cert at no cost on Basic tier or higher; **Add certificate later** is the pick for Shared tier, for bring-your-own certificates, or during a live migration. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain)) ([Learn](https://learn.microsoft.com/en-us/azure/app-service/configure-ssl-certificate))
- Binding choice: **SNI SSL** scales to many domains on a shared IP; **IP SSL** is a single-certificate, dedicated-public-IP option limited to Standard tier and above. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Flow choice: if a brief DNS interruption is acceptable, map the name directly; if you need continuous resolution, follow the migration flow of verification TXT record first, then **Validate**, then **Add**, then remap the live record. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Timing choice for managed certs: when migrating a live domain, an App Service managed certificate can only be added after the active DNS name has been remapped. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- A domain can be moved between apps in the same subscription or across subscriptions, but for a zero-downtime move the source and target apps must share the domain name at the same moment, so they must sit in different deployment units. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))

## Gotchas

- Do not press **Validate** too early in the direct-mapping flow: the two DNS records must already exist at the provider or the checks fail. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- The TXT record is not strictly mandatory, but skipping it is strongly discouraged, and domains configured before it existed should add it now to close the subdomain-takeover risk. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- A wildcard `*` TXT record does not validate subdomains that already have their own **CNAME record**; create a separate **TXT** record for each such subdomain. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Validation during migration succeeds with only the domain verification ID (the **TXT** record), even though the dialog still shows two records as required for the domain to function. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- After adding a domain with **Add certificate later**, the entry stays flagged with a red X and **No binding** until you add a private certificate and configure the binding. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Until a certificate binding exists, browser HTTPS requests to that domain return an error or a warning depending on the browser. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- If the source and target apps share a deployment unit, the zero-downtime domain transfer cannot work, and the only remedy is to keep creating **App Service plan** instances in new resource groups or regions until the FTP/S hostname differs. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Naming differs between the two guides for the root verification record: the add-domain dialog shows host `asuid`, while the migration guide uses `_asuid_` for the root and wildcard. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/manage-custom-dns-migrate-domain))
- Some providers, GoDaddy among them, do not apply record edits until you click a separate **Save Changes** link, so verify the save actually happened. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
- Changes to App Service Managed Certificates took effect on July 28, 2025 and alter how certificates are issued and renewed in certain scenarios, so review the ASMC details before relying on automatic renewal. ([Learn](https://learn.microsoft.com/en-us/azure/app-service/app-service-web-tutorial-custom-domain))
