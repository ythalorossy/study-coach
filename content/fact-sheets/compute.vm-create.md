# Create a virtual machine

## Key concepts

- An Azure VM is on-demand, scalable compute that gives more control than other compute options, yet you still configure, patch, and update the guest OS yourself. Uses include development and test, applications with fluctuating demand, and an extended datacenter joined to your network through a virtual network. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Creating a VM also creates a virtual network, a NIC, a private IP and sometimes a public IP, an NSG, an OS disk plus possible data disks, and sometimes an OS license; each adds its own cost. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Supporting resources default to the same resource group as the VM, and the portal derives similar names for them from the VM name. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Location means the region holding the VM's virtual hard disks: choose it in the portal, run `Get-AzLocation`, call the REST List locations operation, or run `az account list-locations`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Size determines processing power, memory, storage capacity, and network bandwidth. Compute is billed hourly by size and OS, and only for minutes used in a partial hour; storage bills separately. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Default subscription quota is 20 VM total cores per region and can be raised through a support ticket. Quota and capacity are checked separately, so an approved quota still fails when the target region or zone has no capacity. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Managed disks remove storage-account setup and scaling work: you set disk size and the Standard (HDD) or Premium (SSD) tier. Build new VMs with managed OS and data disks via CLI or the portal, and convert VMs that use unmanaged disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Marketplace images cover supported Linux and Windows distributions. The portal fills image values in automatically once you select an image, while CLI, PowerShell, and REST queries list publishers, offers, and SKUs. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- New Generation 2 VMs can use Trusted Launch as default (TLaD): any new Gen2 VM created through any client tool enables secure boot and vTPM automatically. Register for TLaD to apply that default behavior in your environments. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))

## Settings and limits

- Portal route: search **Virtual machines**, pick **Create**, then **Virtual machine** to open the **Create a virtual machine** page. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Windows **Instance details**: **Virtual machine name** `myVM` and **Image** `Windows Server 2022 Datacenter: Azure Edition - x64 Gen 2`; remaining fields arrive pre-filled with defaults. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Windows **Administrator account**: a username such as `azureuser` plus a password of at least 12 characters that meets the defined complexity requirements. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Windows **Inbound port rules**: set **Allow selected ports**, then choose **RDP (3389)** and **HTTP (80)**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Windows **Management** tab, **Auto-shutdown** section: select **Enable auto-shutdown**, choose **Shutdown time** and **Time zone** (UTC default), and optionally get an e-mail warning before shutdown. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Linux **Project details**: confirm the subscription, then choose **Create new resource group** with a name such as `myResourceGroup`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Linux **Instance details**: **Virtual machine name** `myVM`, **Availability options** set to **No infrastructure redundancy required**, **Security type** set to **Standard**, **Image** `Ubuntu Server 22.04 LTS - Gen2`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Linux **Administrator account**: **Authentication type** **SSH public key**, **Username** `azureuser`, **SSH public key source** left at **Generate new key pair**, **Key pair name** `myKey`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Linux **Public inbound ports**: set **Allow selected ports**, then choose **SSH (22)** and **HTTP (80)**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- At **Create**, the **Generate new key pair** window appears: select **Download private key and create resource** and the file arrives as `myKey.pem`; note its path. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- On macOS or Linux, restrict the key with `chmod 400 ~/Downloads/myKey.pem`, then run `ssh -i ~/Downloads/myKey.pem azureuser@10.111.12.123` with the VM's public IP. Windows users connect from PowerShell. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- For later VMs, pick **Use a key stored in Azure** as **SSH public key source**; the private key stays on your computer, so nothing is downloaded again. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Windows access: **Connect**, then **Connect** again, **Check access** to test port 3389, then **Download RDP file**. A certificate warning is normal; answer **Yes** or **Continue**. On a Mac, use an RDP client such as Remote Desktop Client. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Billing: every VM gets an OS disk and a local disk, and local disk storage is free. The OS disk is usually 127GiB, smaller for some images, billed at the normal disk rate, and can be Premium SSD or Standard HDD. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Network limits: NICs have no separate charge, but their number is limited by the VM size. NSGs are free and control traffic to and from the VM, for example permitting port 22 for SSH while blocking port 80. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Local temporary storage sits on the host rather than in remote Azure Storage and suits caches, buffers, and temp files. It has no backup, vanishes when the VM is deallocated or deleted, and is recreated at startup. Sizes with `d`, such as `Dadsv6`, `Eadsv6`, and `FXmdsv2`, add dedicated local NVMe capped at 2,040 GiB that bypasses the VM's IOPS and throughput caps. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))

## Compare and choose

- Pick a single VM for one controlled instance with a specific configuration. Pick Virtual Machine Scale Sets for a load-balanced group whose instance count automatically rises and falls with demand or a schedule, with centralized management, configuration, and updates. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Availability Zones are physically separate zones inside one region. Two or more instances spread over two or more zones in that region keep at least 99.99% connectivity to at least one instance; scale-set instances may instead run across several zones, one zone, or regionally. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- For new deployments choose managed OS and data disks, and convert existing unmanaged-disk VMs. Keep persistent data on a separate data disk so it can be detached and attached to a replacement VM if the original fails. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Authentication: the Linux quickstart uses **SSH public key** with **Generate new key pair** or **Use a key stored in Azure**, while the Windows quickstart uses a username plus password of at least 12 characters meeting complexity rules. Azure can create and store the SSH key pair, putting the public key in the VM while you keep the private key. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Use local ephemeral storage for data that need not survive, and managed Premium SSD or Standard HDD disks for anything persistent. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Auto-shutdown placement: configure it during Windows creation on the **Management** tab, but for Linux set it later from the VM's **Operations** section by selecting **On**, choosing the time and **Time zone** (UTC default), and choosing **Save**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- List images in the portal or query them in PowerShell with `Get-AzVMImagePublisher -Location location`, `Get-AzVMImageOffer -Location location -Publisher publisherName`, and `Get-AzVMImageSku -Location location -Publisher publisherName -Offer offerName`, or in CLI with `az vm image list-publishers --location location` plus matching `list-offers` and `list-skus` commands. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Region-wide recovery: Azure Site Recovery replicates VMs to a chosen region without being limited to paired regions, supports a recovery plan for automated failover, and allows testing failover beforehand without touching production or ongoing replication. Waiting for Azure to recover needs no action from you but gives no data-synchronization guarantee. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))

## Gotchas

- The default size and price are examples only. Size availability and pricing depend on your region and subscription, so the portal default may not match what you pay. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- Creating a VM creates billable companions: the virtual network, IP addresses, OS disk, and sometimes an OS license whose cost varies with core count and can drop with Azure Hybrid Benefit. Local disk storage stays free. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- A Windows password under 12 characters, or one that fails complexity rules, is rejected at creation. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- The Linux private key is downloaded only when you select **Download private key and create resource** in the **Generate new key pair** dialog. If `myKey.pem` is lost, you need another access path, such as a new key pair or a password reset. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- The SSH private key needs restrictive permissions, hence `chmod 400` on macOS and Linux. Azure places the public key in the VM and you keep the private key locally. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- **Allow selected ports** opens every checked port to the VM's public IP through the NSG, so adding **HTTP (80)** next to **RDP (3389)** or **SSH (22)** also exposes web traffic. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- The RDP certificate warning during sign-in is expected because the VM certificate is not yet trusted; select **Yes** or **Continue** to connect. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Quota approval is not capacity: deployment can still fail when the target region or availability zone lacks room for the chosen size and zone. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Ephemeral and local temporary data disappears when the VM is deallocated or deleted, so keep nothing you need there. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/overview))
- Deleting the resource group removes the VM and its related resources; deleting only the VM can leave supporting resources behind that still bill you. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/windows/quick-create-portal))
- Some users now see an option to create VMs in multiple zones, but the Linux quickstart's **No infrastructure redundancy required** choice provides no zone redundancy. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
- On Ubuntu, install NGINX with `sudo apt-get -y update` and `sudo apt-get -y install nginx`; SUSE Linux uses `sudo zypper --non-interactive update` and `sudo zypper --non-interactive install nginx`, RHEL uses `sudo dnf update` and `sudo dnf install nginx`, and Windows IIS uses `Install-WindowsFeature -name Web-Server -IncludeManagementTools`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/linux/quick-create-portal))
