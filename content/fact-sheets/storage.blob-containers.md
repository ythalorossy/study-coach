# Create and configure a container in Azure Blob Storage

## Key concepts

- Azure Blob Storage is Microsoft's object store for unstructured data (text or binary with no fixed data model), built for serving images/documents straight to a browser, distributed file access, audio and video streaming, log file writing, backup/restore, disaster recovery, archiving, and data analytics. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Data is organised in three nested resources: the **storage account**, a **container** inside it, and a **blob** inside the container. Every object address combines the account name with the Blob Storage endpoint, e.g. `https://mystorageaccount.blob.core.windows.net`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- A container is the directory-equivalent grouping layer: one storage account can hold an unlimited number of containers, and each container can hold an unlimited number of blobs. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Addressing formats: container = `https://myaccount.blob.core.windows.net/mycontainer`; blob = `https://myaccount.blob.core.windows.net/mycontainer/myblob`, or with a virtual directory `https://myaccount.blob.core.windows.net/mycontainer/myvirtualdirectory/myblob`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Three blob types exist. **Block blobs** hold text and binary data as individually managed blocks, up to roughly 190.7 TiB. **Append blobs** are block-based but optimised for append-only writes such as VM logs. **Page blobs** store random-access files up to 8 TiB, typically VHDs acting as VM disks. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Clients reach Blob Storage over HTTP/HTTPS from anywhere via the **Azure Storage REST API**, `Azure PowerShell`, `Azure CLI`, or a client library (.NET, Java, Node.js, Python, Go); connections can also be made securely with **SFTP**, and containers can be mounted with **NFS 3.0**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Storage account options: **General-purpose v2** (Standard tier) is the recommended type for most scenarios, including blobs, file shares, queues and tables; **Premium block blob** is for very high transaction rates, smaller objects, or consistently low latency; **Premium page blob** is for page blobs only. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Blob Storage also underpins **Azure Data Lake Storage**, adding a hierarchical file system plus low-cost tiered storage, high availability, strong consistency and disaster recovery. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Bulk data movement options: **AzCopy** (command line, Windows and Linux, across containers or accounts), the **Azure Storage Data Movement** .NET library that AzCopy is built on, **Azure Data Factory** (supports account key, shared access signature, service principal, or managed identity), **Blobfuse** (Linux virtual file system), **Azure Data Box / Data Box Disk / Data Box Heavy** for offline shipping, and the **Azure Import/Export** service. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Anonymous read access is optional and off by default: unless it is explicitly enabled, every request to a container and its blobs must be authorized. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))

## Settings and limits

- Container names must be a valid DNS name because they form part of the container URI: 3 to 63 characters, must begin with a letter or a number, may contain only lowercase letters, numbers and the dash (`-`), and two or more consecutive dashes are not allowed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Blob names may contain any combination of characters, must be at least 1 and at most 1,024 characters, are case-sensitive, and reserved URL characters must be properly escaped. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Path-segment limits for a blob name: no more than 254 path segments when the storage account does **not** have hierarchical namespace enabled, and no more than 63 (counting segments for the container name and account host name) when hierarchical namespace **is** enabled. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Portal path to create a container: open the storage account → left menu **Data storage** → **Containers** → **+ Container** → type the name → pick the anonymous access level (default **Private (no anonymous access)**) → **Create**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-quickstart-blobs-portal))
- Storage-account-level gate: in the portal go to the storage account → **Configuration** under **Settings** → set **Allow blob anonymous access** to **Enabled** or **Disabled**; the underlying ARM property is `AllowBlobPublicAccess` and is available on all storage accounts created with the Azure Resource Manager deployment model. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Allowing or disallowing anonymous access requires Azure Storage resource provider version **2019-04-01** or later. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Container anonymous access levels: **Private** (portal) / **Off** (PowerShell) = container and blobs only via authorized requests, and this is the default for all new containers; **Blob** = blobs readable anonymously but container data is not, so anonymous clients cannot enumerate the blobs; **Container** = container and blob data readable anonymously. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- The level is set at container creation time or changed later: storage account overview → **Data storage** → **Containers** → tick the containers → **Change access level** → choose a value in the **Anonymous access level** dropdown → **OK**; verify by reopening **Change access level**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- The access level can only be set at container level; it cannot be changed for an individual blob. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- To set a container's level you first need anonymous access allowed on the account (`AllowBlobPublicAccess`) plus write permission on the container; if the account disallows anonymous access the option is disabled and can't be selected. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Checking the setting across containers: with `Get-AzStorageAccount -ResourceGroupName "<resource-group>" -Name "<storage-account>"`, then `Get-AzStorageContainer -Context $ctx | Select Name, PublicAccess`, which lists each container's `PublicAccess` value; performance suffers on accounts with many containers. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- A change to the account's anonymous access setting can take up to 30 seconds to fully propagate. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Setting `AllowBlobPublicAccess` needs `Microsoft.Storage/storageAccounts/write`, granted by the **Owner**, **Contributor** and **Storage Account Contributor** roles; the role assignment must be scoped to the storage account or higher. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Those administrative roles also carry `Microsoft.Storage/storageAccounts/listkeys/action`, so the holder can reach all data in the account through the account access keys, while the action alone still does not allow changing `AllowBlobPublicAccess`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- For data access without configuration rights, assign **Storage Blob Data Contributor**, **Storage Blob Data Reader**, or **Reader and Data Access**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Even when anonymous access is granted, network **firewall rules** configured on the storage account stay in effect and keep blocking traffic according to their ACLs. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Disallowing anonymous access on the account does not affect static websites: the **$web** container is always publicly accessible. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Portal blob operations in a container: **Upload** (expand **Advanced** to set extra options such as **Upload to folder** to place the blob in a new or existing virtual folder), right-click → **Download**, and **Delete** on ticked blobs, where the confirmation also asks whether to delete blob snapshots. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-quickstart-blobs-portal))

## Compare and choose

- Block vs append vs page blob: choose **block blob** for general files, images and video; **append blob** when the workload only adds to the end, such as logging; **page blob** when you need a random-access virtual disk such as a VHD. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- **Blob** vs **Container** level: pick **Blob** when anonymous clients only need specific blob contents; pick **Container** when they must also list what is inside the container — with **Blob** the container listing is blocked, with **Container** clients can list blobs but still cannot list containers in the account. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- General-purpose v2 vs Premium: choose **General-purpose v2 (Standard)** for almost all Blob Storage scenarios and for accounts also serving file shares, queues and tables; choose **Premium block blob** for high transaction rates, small objects or strict latency; **Premium page blob** only for page blob workloads. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Moving existing data: use **AzCopy** for ad hoc command-line transfers, **Azure Data Factory** for scheduled pipelines with key/SAS/service principal/managed identity auth, **Blobfuse** to browse existing block blob data from Linux, and **Azure Data Box** or **Import/Export** when the dataset or network makes uploading over the wire unrealistic. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Role choice: to toggle `AllowBlobPublicAccess` or create accounts assign **Owner**, **Contributor** or **Storage Account Contributor** at the storage account scope or above; to just read or write blob data assign **Storage Blob Data Contributor** or **Storage Blob Data Reader** instead, following least privilege. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Hierarchical namespace on or off: leaving it off gives 254 path segments per blob name; enabling it caps them at 63. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))

## Gotchas

- Enabling anonymous access means any client, anywhere, can read that container's data — treat it as a security risk and remediate it on the account if the scenario does not require it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Two settings interact: the account's `AllowBlobPublicAccess` is the master switch. If it disallows anonymous access, every container in that account is private regardless of the container's own level, and the account setting overrides the container setting. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Allowing anonymous access on the account is not enough: blob data stays unavailable anonymously until someone explicitly configures the container's access level. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- After you disallow anonymous access on the account, clients using the anonymous bearer challenge get a **403 (Forbidden)** instead of the usual **401 (Unauthorized)**; keeping all containers private avoids this confusion. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- If an anonymous-eligible request arrives with an `Authorization` header, the service ignores the anonymous setting and authorizes using the supplied credentials instead. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Even at the **Container** level, anonymous clients cannot read container permission settings or container metadata — only the container listing and blob data. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
- Avoid blob names ending in a dot (`.`), a forward slash (`/`), or a combination of the two, and no path segment should end with a dot. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Container names are lowercase-only and single dashes between words; double dashes break the DNS name requirement. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blobs-introduction))
- Deleting a container deletes every blob inside it — there is no step that preserves the data. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-quickstart-blobs-portal))
- Enabling **Data Lake Storage Gen2**, **NFS 3.0** or **SFTP** on the storage account can change whether this anonymous access feature behaves as described, so verify feature support in those accounts. ([Learn](https://learn.microsoft.com/en-us/azure/storage/blobs/anonymous-read-access-configure))
