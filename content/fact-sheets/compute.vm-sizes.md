# Manage virtual machine sizes

## Key concepts

- A VM size (SKU) fixes the vCPU count, memory, storage capability and network bandwidth given to a virtual machine, so it is chosen from the workload's CPU, memory, storage and network requirements. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Azure sorts sizes by intended workload, separating basic instances from lines aimed at balanced general use, CPU-heavy processing, memory-heavy processing, storage-heavy processing, GPU acceleration, FPGA acceleration and high performance computing. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Each size name splits into a series and a size: the series groups configurations with similar hardware and features, while the size is the individual configuration with its own vCPUs, memory and accelerators. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Family codes are usually one letter (D, E, F), though GPU families use two (ND, NV), and a subfamily adds another uppercase letter, so `DCads_v5` names the `DCadsv5-series`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The processor vendor is encoded too: no vendor letter means Intel x86-64, `a` means AMD and `p` means ARM such as Microsoft Cobalt or Ampere Altra. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Version digits appear only when a series has more than one version, so a first version often leaves them out (HB-series, B-series); extra feature letters may be absent (Dv5-series) or numerous (Dplds_v6-series). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Some names contain spacers, as in `ND_H100_v5-series`, where an underscore separates the GPU identifier from the rest of the name. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Once a VM exists you can move it to a larger or smaller size, and the operation works both while it runs and after it has been deallocated. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The target size must exist on the hardware cluster that hosts the VM; when the cluster does not offer it, the VM has to be deallocated first. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Changing the size of a running machine reboots it, so plan for downtime and be careful with applications that keep state. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The size catalog covers both major operating systems plus Flexible and Uniform scale sets. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The resize walkthrough applies to Linux and Windows VMs and to Flexible scale sets, but not to Uniform scale sets. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))

## Settings and limits

- In the portal, find **virtual machines** under **Services**, open the **Virtual machines** list and select the VM; on its menu, in **Availability + scale**, choose **size**, pick a compatible entry and select **Resize**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- A size that is missing from the list while the VM runs can reappear after the VM is stopped, because a stopped machine exposes more choices. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- `Get-AzVMSize -ResourceGroupName $resourceGroup -VMName $vmName` lists the sizes offered by the VM's own hardware cluster, which are the valid resize targets. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- To resize in PowerShell, fetch the VM with `Get-AzVM`, assign the new SKU to `$vm.HardwareProfile.VmSize`, then persist it with `Update-AzVM -VM $vm -ResourceGroupName $resourceGroup`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Running PowerShell locally requires `Import-Module Az`, `Connect-AzAccount` and `Select-AzSubscription -SubscriptionId '<subscriptionID>'`, and the local run may still need the VM to restart to take effect. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- For a VM in an availability set, if the target size is missing from the `Get-AzVMSize` results, deallocate every VM in the set with `Stop-AzVM -Force -NoWait`, apply the new size to each, then bring them back with `Start-AzVM`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Availability sets can also require every VM in the set to move to the new size, because one resized member can leave the others on their previous size. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The CLI path needs the latest Azure CLI installed and an authenticated session created with `az sign-in`, using an account authorized to update the VM in its subscription. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- `az vm list-vm-resize-options --resource-group $resourceGroup --name $vm --query "[].name"` returns the allowed target sizes; the documented single-VM script stops with an error when the wanted size is absent. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The documented CLI sequence is `az vm deallocate --resource-group $resourceGroup --name $vm`, then `az vm resize --resource-group $resourceGroup --name $vm --size $size`, then `az vm start --resource-group $resourceGroup --name $vm`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The availability-set CLI sample collects instance IDs with `az vmss list-instances`, deallocates them with `az vm deallocate --ids $vmIds --no-wait`, sets the size with `az vmss update --set virtualMachineProfile.hardwareProfile.vmSize=$newVmSize`, and restarts them with `az vmss start --instance-ids $vmIds`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- In Terraform, change the `size` argument in the `azurerm_linux_virtual_machine` or `azurerm_windows_virtual_machine` resource, preview with `terraform plan -out main.tfplan`, then apply with `terraform apply main.tfplan`; the sample value is `size = "Standard_DS1_v2"`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Linux VMs can be resized across the local temp disk boundary, so a size with a local temp disk and one without can be converted into each other. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Windows VMs are restricted to like-for-like changes: local temp disk to local temp disk, or no local temp disk to no local temp disk. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- To move a Windows VM that has no local temp disk onto a size that has one, snapshot the VM, create a disk from that snapshot, then create the new VM from the disk. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- A SCSI-based VM size cannot be resized to a remote NVMe-enabled size. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Premium Storage workloads need an `s` version of the size, for example `Standard_E4s_v3` instead of `Standard_E4_v3`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Candidate sizes are limited by the deployment region and by the VM's hardware cluster; Azure VM Selector narrows options by workload, operating system and software, plus region, while the listing commands return only cluster-allowed sizes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))

## Compare and choose

- When the workload is CPU-heavy, such as a database server or a web front end with heavy traffic, pick a SKU offering more cores, which points to the Compute optimized line. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- When the workload is memory-heavy, such as a machine learning model or a big data job, pick a SKU offering more RAM, which points to the Memory optimized line. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- If the VM is running out of disk capacity, choose a SKU with more storage, which points to the Storage optimized line. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Sizes in the general-purpose tier spread capacity evenly between processor and memory, making them sensible for non-production use such as development or test environments, compact databases and lightly loaded web servers. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The A family is the cheapest, entry-level line, aimed at dev/test, small applications and small databases where budget matters more than performance. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The B family is burstable and the only Azure VM type that meters CPU with credits: credits accumulate below the base CPU threshold, are spent above it, and once depleted the VM is throttled back to base performance until they rebuild. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The D family gives you quicker processors and more RAM per core than the A line, so it carries line-of-business applications, sizeable relational databases, busy web and application tiers, queued batch work and game servers. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- The DC family adds confidential computing, where Trusted Execution Environments (TEEs) run in hardware, making it a fit for personal, financial or health data and for regulated workloads. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- F keeps a processor-heavy balance, which fits medium-load web servers, network appliances, batch queues, application servers, analytics and gaming. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- FX pairs fast single-core speed with a big per-core cache on Intel Ice Lake silicon, appealing to Electronic Design Automation (EDA) teams, database servers needing large cache layers and analytics that works on data held in RAM. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- E favors memory over cores, which fits database servers, large cache layers, RAM-resident analytics, heavy SQL Server or NoSQL engines, ERP and CRM platforms, big data pipelines, SAP HANA and data warehousing. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- Eb keeps that memory emphasis and adds strong remote storage performance, while EC layers confidential computing with TEEs for sensitive workloads. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- M is the ultra memory-optimized family for extreme needs: enormous in-memory databases, data warehousing, HPC, heavy SQL Server and other RDBMS workloads, scientific simulations, real-time processing, large ERP platforms and dense virtualization. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- L favors local disk speed, pairing large attached disks with high throughput and I/O for massive datasets, SQL or NoSQL engines, warehouse workloads and very chatty transactional stores; named examples include Cassandra, MongoDB, Cloudera and Redis. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- GPU families split by job: NC uses NVIDIA GPUs for AI/ML training, HPC and 3D rendering; ND adds large memory for deep learning; NG uses AMD Radeon PRO GPUs for cloud gaming and remote desktops; NV covers VDI, rendering, high-resolution imaging and video streaming. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- NP pairs AMD Xilinx Alveo U250 FPGA boards with Intel Xeon 8171M CPUs, and targets inference work, stream transcoding, custom database acceleration, telecom signal handling and other low-latency processing. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- HPC families differ by strength: HB pairs AMD EPYC with high memory bandwidth for CFD, FEA, weather, seismic and genomics work; HC gives Intel Xeon Scalable high-density compute for FEA, molecular dynamics and computational chemistry; HX supplies large memory for EDA. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))

## Gotchas

- If a resize fails, Azure still records the size you asked for in the VM model, and every GET call reports that requested value, even though the machine keeps executing on the old size until a later resize succeeds. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Any dynamic IP address attached to the VM is released when it is deallocated, while the OS disk and the data disks stay untouched. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- The size string itself decides storage support: the `s` variant enables Premium Storage, so `Standard_E4_v3` and `Standard_E4s_v3` are not interchangeable. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- B-series credit exhaustion throttles the VM to base CPU performance while credits rebuild, so B-series is a poor fit for sustained full-CPU demand. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- HC-series retires on May 31, 2027, after which remaining instances are deallocated, stopped and lose SLA and support; sales of one-year and three-year Reserved Instances ended April 2, 2026, so new deployments should consider HBv5 or HX. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/overview))
- When the wanted size is missing from the current cluster, an availability-set deployment means taking down every member at once, resizing them all and starting them again. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
- Resizing scales one machine up or down; sustained growth is better handled by running multiple instances and scaling out. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/sizes/resize-vm))
