# Manage data by using Azure Storage Explorer and AzCopy

## Key concepts

- AzCopy v10 is the only currently supported AzCopy line, and it runs only on officially maintained Windows, Linux, and macOS versions; older builds are handled as the previous version. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- AzCopy is a command-line utility that copies data to, from, or between storage accounts: a local source to Azure, Azure to a local destination, or one account to another. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- It offers native copy and sync commands for one-time copies and ongoing mirroring, and it can move data between services such as a blob container and a file share. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- AzCopy authorizes through Microsoft Entra ID, which supplies credentials once instead of adding a SAS token to every command, or through SAS tokens appended per URL; Entra principals can be a user identity, managed identity, or service principal. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Azure Storage Explorer is a standalone app for Windows, macOS, and Linux; it connects either by signing in to Azure for subscriptions and their resources, or by attaching to one individual storage resource. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Full use after subscription sign-in needs management (Azure Resource Manager) and data-layer permissions covering the account, its containers, and their data; with data-layer permissions only, attach to the resource using **Sign in using Microsoft Entra ID**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- AzCopy user identity authorization suits interactive or development work and can use environment variables, `azcopy login`, or an existing Azure CLI or Azure PowerShell session. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))

## Settings and limits

- Linux can install AzCopy with the distribution package manager, the recommended route for dependency resolution and updates; other operating systems use a portable binary for Windows 64-bit, 32-bit, ARM64, Linux x86-64, ARM64, macOS, and macOS ARM64, shipped as zip on Windows and macOS and tar on Linux. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Put the AzCopy folder on the system path to run `azcopy` from any directory; otherwise change into it and run `azcopy` or `.\azcopy`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy -h` lists commands and `azcopy list -h` shows one command's help; the commands are `azcopy bench` (benchmark), `copy`, `doc` (Markdown output), `env` (behavior environment variables), `jobs` with `clean`, `list`, `remove`, `resume`, `show`, plus `list`, `login`, `login status`, `logout`, `make`, `remove`, `sync`, and `set-properties`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy copy` copies source data to a destination and `azcopy sync` replicates source onto destination; `azcopy make` creates a container or file share, `azcopy remove` deletes blobs or files, `azcopy set-properties` changes blob access tier while replacing metadata and index tags, and no AzCopy command renames files. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy jobs resume <job-id>` restarts a job, `azcopy jobs show <job-id>` details it, `azcopy jobs remove <job-id>` deletes that job's files, and `azcopy jobs clean` deletes log and plan files of every job. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- SAS authorization appends the token to every source or destination URL, where `sv` is service version, `sp` permitted operations, `st` and `se` the validity period, `spr` allowed protocol, and `sig` the signature; `--recursive=true` copies all files and subdirectories of the directory. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Since v10.34.0, AzCopy sends usage telemetry, including storage account names and pseudonymous installation and job identifiers, unless `--disable-telemetry=true` is passed. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Downloads require **Storage Blob Data Reader** for Blob Storage or **Storage File Data Privileged Reader** for Azure Files; uploads require **Storage Blob Data Contributor** or **Storage Blob Data Owner** for Blob Storage, or **Storage File Data Privileged Contributor** for Azure Files. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- Role assignments can take five minutes to propagate; in a hierarchical-namespace account, adding the principal to the target container or directory ACL replaces those roles and needs `write` on the target directory plus `execute` on the container and each parent directory. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- `export AZCOPY_AUTO_LOGIN_TYPE=DEVICE` followed by any AzCopy command returns a code and website URL; after entering the code and selecting **Next**, the token is dropped from memory when the operation ends. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- `azcopy login` saves its OAuth token in a system secret store and fails without one, such as Linux with no keyring; `azcopy login --tenant-id=<tenant-id>` targets one organization, whose tenant ID sits under **Tenant properties > Tenant ID** in the portal. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- Reuse a CLI session with `export AZCOPY_AUTO_LOGIN_TYPE=AZCLI` plus `export AZCOPY_TENANT_ID=<tenant-id>`, or a PowerShell session with `$Env:AZCOPY_AUTO_LOGIN_TYPE="PSCRED"` plus `$Env:AZCOPY_TENANT_ID=<tenant-id>`. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- Latest Storage Explorer needs Windows 11 or Windows 10, 64-bit application support (from version 1.30.0), and an architecture-matching .NET 10 runtime (from version 1.42.0); the installer adds the runtime if missing but possibly not the newest build, and updating it is your responsibility. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Subscription sign-in runs **View** > **Account Management** (or **Manage Accounts**) > **Add account...**, sets **Select Resource** to **Subscription**, picks an environment in **Select Azure Environment** (global Azure, a national cloud, or Azure Stack), selects **Next**, signs in, ticks subscriptions, then selects **Apply**, which fills **ACCOUNT MANAGEMENT** and **EXPLORER**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- To attach one resource, use the **Connect** button, pick its type in **Select Resource**, choose authentication, enter display name and details, confirm on **Summary**, then select **Connect**; account connections land under **Local & Attached** > **Storage Accounts**, other types under **(Attached Containers)** in the matching group, so an ADLS Gen2 container appears under **Blob Containers**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Account name and key: select **Storage account** then **Account name and key**, entering display name, account name, one key, and Azure environment; keys are under **Settings** > **Access keys**. SAS connection string: select **Storage account** then **Shared access signature (SAS)** and paste a string with `SharedAccessSignature=...` plus blob, file, queue, and table endpoints. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- SAS URL: choose **Shared access signature (SAS)** for a blob container, ADLS Gen2 container or directory, file share, queue, or table and paste the URI; the sample blob SAS uses `sr=c` for container scope and `sp=rl` for read and list. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Entra attachment: in **Select Resource** choose **Blob container**, **ADLS Gen2 container**, or **Queue**, select **Sign in using Microsoft Entra ID**, pick an account and tenant with access, add display name and URL, then confirm on **Summary** and select **Connect**. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Emulator: choose **Local storage emulator**, enter display name and each service's port, leaving unused ports blank; default-port emulators appear under **Local & Attached** > **Storage Accounts** > **Emulator - Default Ports**, and Storage Explorer never starts the emulator for you. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Issue a SAS by right-clicking the account, choosing **Get Shared Access Signature**, setting timeframe and permissions on the **Shared Access Signature** page, selecting **Create**, then copying the **Connection string** or raw **Query string**; service-level SAS also exists. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Search filters in the **EXPLORER** pane as you type; deselect unrelated subscriptions in **Account Management** to speed it up, or right-click a node and select **Search From Here** to search only below it. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))

## Compare and choose

- Use AzCopy for repeatable, scheduled, or continuous integration transfers, since it is scriptable and offers both copy and sync; use Storage Explorer for interactive GUI work such as browsing containers, attaching one resource, issuing SAS tokens, and searching. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy sync` mirrors source onto destination for ongoing replication, while `azcopy copy` suits a one-off copy. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Prefer Entra ID for recurring AzCopy automation, because a SAS token must accompany every URL, while Entra credentials are supplied once or reused from Azure CLI or Azure PowerShell. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Prefer `AZCOPY_AUTO_LOGIN_TYPE=DEVICE` over `azcopy login` on machines without a secret store, where sign-in has nowhere to keep its token. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- Storage-account connections in Storage Explorer accept Microsoft Entra ID, account name and key, and a SAS connection string or URL, but not anonymous access; blob containers and ADLS Gen2 containers or directories accept Microsoft Entra ID, SAS URL, and anonymous access, but not account key; file shares, queues, and tables accept Microsoft Entra ID or SAS URL only. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- Use a SAS connection string for a whole storage account and a SAS URL for a single blob container, ADLS Gen2 container or directory, file share, queue, or table. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- For migration into Azure Storage above 1 TB, choose the managed service Azure Storage Mover rather than AzCopy. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))

## Gotchas

- Storage account ownership does not automatically grant AzCopy data access; Entra role assignments or a SAS token are still required. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- AzCopy cannot run a transfer while another process is modifying its source or destination. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy set-properties` replaces metadata and index tags rather than merging them, so existing values are lost. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- Telemetry is on by default from v10.34.0 and includes storage account names, so pass `--disable-telemetry=true` when it must not leave the machine. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- `azcopy login` cannot work without an operating system secret store, and a newly assigned role can fail for up to five minutes while it propagates. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- In a hierarchical-namespace account the ACL needs `write` on the target directory and `execute` on the container and every parent directory, so one missing ancestor permission breaks the path. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- `AZCOPY_AUTO_LOGIN_TYPE=DEVICE` must be set in the same session as the AzCopy command, and its token is discarded from memory once the operation finishes. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-authorize-user-identity))
- Public anonymous access is unavailable for storage accounts, file shares, queues, and tables, and account name and key never attaches directly to a blob container, file share, queue, or table. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
- A SAS expires on its own window from `st` to `se`; after `se` passes, the attached connection or the AzCopy command using that URL fails. ([Learn](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-v10))
- The .NET 10 runtime installed by Storage Explorer may not be current, and an ADLS Gen2 container connection shows under **Blob Containers** rather than a separate ADLS group. ([Learn](https://learn.microsoft.com/en-us/azure/storage/storage-explorer/vs-azure-tools-storage-manage-with-storage-explorer))
