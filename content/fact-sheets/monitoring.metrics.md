# Interpret metrics in Azure Monitor

## Key concepts

- Azure Monitor Metrics stores numeric data from monitored resources in a time-series database; a metric is a number sampled at regular intervals that describes one aspect of a system at a point in time. Metrics and logs are the two halves of the Azure Monitor data platform. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Three implementations exist: **platform metrics** (automatic, no configuration, no ingestion or storage cost), **advanced platform metrics** (paid public preview, opted in per resource, deeper data for supported providers), and **metrics in an Azure Monitor workspace** (Prometheus and OpenTelemetry from Kubernetes, VMs, Arc-enabled servers, apps). ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Platform metrics need no setup, every resource type emits its own metric set, and collection runs at a one-minute frequency unless the metric definition says otherwise. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- A stored time series holds the collection time, the associated resource, a namespace acting as the metric category, the metric name, the value, and any dimensions; dimension limits vary by implementation. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Dimensions are name/value pairs that add context — an available disk space metric with a **Drive** dimension showing **C:** and **D:**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- A nondimensional metric (network throughput) only answers "value at a given time"; dimensions such as **IP** and **Direction** let you ask per-IP throughput and sent versus received. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Dimension names and dimension values are case-insensitive. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- **Metrics explorer** charts metric values over time to correlate trends and investigate spikes and dips; open it from the **Azure Monitor** overview or a resource's **Monitoring** section by choosing **Metrics**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Metrics explorer** can chart Prometheus data with PromQL (label filtering, math, aggregation across series), but only for metrics in an Azure Monitor workspace, opened by picking **Metrics** on that workspace. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Drill into Logs** links a spike to **Activity log** (management plane: what, who, when for `PUT`, `POST`, `DELETE`; one per subscription), **Resource logs** (data plane; must be enabled) and **Recommended log** (scenario queries); supported providers are Application Insights, Autoscale, App Service and Storage. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Platform and advanced platform metrics can be pulled with the Azure CLI, the Azure PowerShell cmdlets, the Metrics REST API, or the .NET, Go, Java, JavaScript and Python client libraries; a custom metrics API loads your own metrics into the same database. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))

## Settings and limits

- The **time picker** sets the **Time range**; the default view is the most recent 24 hours, and options include the last 12 hours or last 30 days. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Time granularity defaults to **Automatic**, which picks the best grain for the range; values in each grain become one point, so 24 hours at a 30-minute grain gives 48 points and at 15 minutes gives 96. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Pan** with the arrow controls at the chart edge: each press shifts the range by half the chart span, moving a 24-hour view to 12 hours ago through a day and a half ago. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Zoom** with the **time brush** over a spike or dip; with **Automatic** granularity the zoom picks a smaller grain, and the new range applies to every chart. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Five aggregations: **Sum** (interval total), **Count** (number of measurements), **Average**, **Min**, **Max**; a default is applied when a metric is added, and unusable options are hidden. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Count** equals **Sum** for metrics always captured as 1, the usual case for distinct-event counters. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Add filter**: pick a dimension from **Property**, choose an operator (equals, `=`, by default), then select values; values missing from the time range's result set aren't offered. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Apply splitting**: choose dimensions, set the display limit (default 10, allowed 1 to 50) and the sort order — **Descending** by default or **Ascending**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Splitting on several dimensions lists segment values comma-separated in the legend; for multi-resource charts split by resource ID or resource group, e.g. percent CPU across nine VMs. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **More options** (...) > **Chart settings** > **Y-axis range** sets bounds or **Auto** to revert; locking the floor at 99 percent exposes a drop from 99.99 percent to 99.5 percent. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Multi-resource charts need the same resource type, location and subscription — others aren't selectable — plus the **Monitoring Reader** role at subscription scope. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Scope picker flow: **Select a scope**, pick a resource (the picker then reveals the subscriptions and resource groups holding it), then **Apply**; for broader queries select a subscription or resource groups, then a resource type and **Location**, expand to verify, then **Apply**. Resource types limited to one resource at a time appear under **All resource types** in the **Resource types** menu. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- **Add metric** adds a line to the current chart (a stacked area chart shows each value plus the combined total); **New chart** starts another, and **More options** (...) offers **Move up**, **Move down** and **Delete**. Don't mix units (milliseconds with kilobytes) or very different scales — use separate charts. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- A rule started from a chart arrives with the chart's resource, metric, split and filter choices pre-filled: on **Condition**, **Signal name** starts as the chart metric and you enter a **Threshold value** drawn as a line in **Preview**; on **Details** set **Name**, **Description** and **Severity** (**Critical**, **Error**, **Warning**, **Informational**, **Verbose**), then **Review + create** and **Create**. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Platform and custom metrics are retained 93 days, but one chart can query only 30 days of data. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))

## Compare and choose

- Storage: platform and advanced platform metrics sit in the Azure subscription; workspace metrics sit in the Azure Monitor workspace. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Cost: platform metrics are free; advanced platform metrics and workspace metrics are paid. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Aggregation: platform and advanced platform metrics are preaggregated; workspace metrics are kept as raw time series. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Analysis: Metrics explorer for platform and advanced platform metrics; PromQL for workspace metrics. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Alerts: metric alert rules for platform and advanced platform metrics; query-based metric alert rules (preview) and Prometheus alert rules for workspace metrics. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Visualization: platform and advanced platform metrics work in Metrics explorer, Workbooks, Azure dashboards and Grafana; workspace metrics use Grafana (including **Azure Managed Grafana**) and Workbooks. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Retrieval: platform and advanced platform metrics come through the Azure Monitor Metrics query APIs, client libraries and CLI tools; workspace metrics come from the Prometheus HTTP API. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Windows: platform and custom metrics keep 93 days and cap each chart at 30 days; Prometheus data is retained for 18 months, and a PromQL query is limited to a 32-day span. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Guest OS counters: sent to Azure Monitor Metrics they keep 93 days; the classic diagnostics extension route to storage guarantees at least 14 days; the retired Log Analytics agent path kept 31 days, extendable to two years. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Application Insights log-based metrics are log queries underneath, so retention is variable and follows the underlying logs (31 days to two years; Application Insights logs store 90 days). ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- For high-volume queries use the **Azure Monitor Metrics Batch REST API**: up to 50 resource IDs in one subscription and region per call, improving throughput and cutting throttling risk; otherwise the standard Metrics REST API. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Filtering vs splitting: filtering picks which dimension values are included, splitting decides whether each value gets its own line or is merged; combining both on one dimension keeps charts readable. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- For VM guest OS metrics use the **Azure Monitor Agent** with a data collection rule for guest OS performance counters — it replaced both the Azure Diagnostics extension (WAD) and the Log Analytics agent for routing. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))

## Gotchas

- The 30-day chart limit sits inside 93-day retention, so an empty or partial chart usually means the start and end dates exceed 30 days — narrow to a 30-day window and slide the chart sideways to reach older points. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- The 30-day limit does not apply to log-based metrics. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Moving or renaming an Azure resource can lose that resource's metric history. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Sources differ in aggregation and latency — platform metrics are preaggregated, Prometheus metrics raw — so one sample time can show different values; the gap fades when latency settles and both use the same granularity. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- With the y-axis locked on count, sum, minimum or maximum aggregations, use a fixed granularity: **Automatic** grain can change when the browser window is resized or the screen resolution changes, which invalidates the y-axis range. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Each plotted point is an aggregate of the values captured in that grain, not a raw sample. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- A dimension value absent from the selected time range won't appear in the filter values dropdown — widen the range before concluding the segment doesn't exist. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- The split limit (1 to 50, default 10) caps how many dimension values are drawn, so extra segments are left out. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Guest OS metrics of a VM never appear automatically — platform metrics cover the resource only; install the **Azure Monitor Agent** and configure a data collection rule. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- The **Log Analytics agent** reached end of life in August 2024, so avoid it for fresh metric collection and pick the **Azure Monitor Agent** instead. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- Native custom metrics stay in public preview for existing implementations and won't reach general availability; new solutions should use the OpenTelemetry-based custom metrics path. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
- PromQL charting only applies to metrics in an Azure Monitor workspace; it can't be pointed at platform metrics. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/analyze-metrics))
- Traffic uses TLS 1.2 (HTTPS); the agent authenticates with certificates on port 443, and Azure Monitor rotates private keys every 90 days. ([Learn](https://learn.microsoft.com/en-us/azure/azure-monitor/metrics/data-platform-metrics))
