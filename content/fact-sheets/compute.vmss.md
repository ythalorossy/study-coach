# Deploy and configure an Azure Virtual Machine Scale Sets

## Key concepts

- Azure Virtual Machine Scale Sets manage a group of load-balanced VM instances whose number can automatically grow or shrink with demand or a fixed schedule, so one workload runs on many identical VMs without configuring each instance by hand. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Documented benefits: managing many VMs easily, high availability and application resiliency across availability zones or fault domains, scaling as resource demand changes, and support for very large deployments. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Flexible orchestration offers a unified experience across the Azure VM ecosystem, with HA guarantees of up to 1,000 VMs spread across fault domains in a region or inside an Availability Zone. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Workloads suited to flexible orchestration: quorum-based workloads, open-source databases, stateful applications, services needing high availability at large scale, deployments mixing VM types or combining Spot and on-demand VMs, and existing Availability Set applications. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- The orchestration mode (Uniform or Flexible) is chosen when the scale set is created and can never be changed or updated afterwards. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Every instance comes from the same base OS image and configuration, so VM size, disk configuration, and installed applications stay consistent across the whole fleet. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- A scale set alone cannot protect you against a data-center failure; spreading instances across Availability Zones within the scale set is what does. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Load balancing differs by layer: the Azure load balancer does basic layer-4 distribution; Azure Application Gateway adds advanced layer-7 handling plus TLS termination. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- There is no extra charge for using scale sets; you pay only for the compute, network, and storage resources they consume. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Instance count can be driven four ways: manually, by a set schedule, by rules based on metric thresholds, or automatically by predictive AI that discovers usage patterns. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Autoscale only works if the scale set has a virtual machine scaling profile that defines the configuration of the instances to add. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Host-based metrics show how scale set VMs are performing and need no agents or data-collection setup; rules built on them can scale out or in on CPU, memory, or disk access. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))

## Settings and limits

- The portal **Basics** tab holds **Project details** (subscription, resource group such as `myVMSSResourceGroup`), **Scale set details** (name, region), **Orchestration**, **Security type**, **Scaling**, **Instance count**, and **Instance details**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Pick **Flexible Orchestration Mode** in the **Orchestration** area and **Trusted launch virtual machines** in **Security type**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- The walkthrough leaves **Scaling** in **Manual** mode and sets the starting **Instance count** to 5; that field accepts values up to 1000. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Select a marketplace **Image** under **Instance details**; deployable images include Windows Server plus Linux images such as RHEL, Ubuntu, and SLES. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- In **Administrator account** you give the admin username plus a credential: an SSH public key or a password. Passwords need a minimum length of 12 characters and must satisfy three of the four complexity rules - one lowercase letter, one uppercase letter, one digit, and one special character. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- For a Linux OS disk image the credential can be an **SSH public key** instead - supply your own or have Azure generate a pair. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Then **Next: Spot** (Spot VM configuration), **Next: Disks** (disk configuration), and **Next: Networking**; the quickstart keeps default Spot and disk configurations. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- On **Networking**, under **Load balancing**, select **Azure load balancer**, then pick an existing load balancer or create a new one. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Finish at **Review + create**, then **Create** once validation passes; to clean up, select the scale set's resource group and **Delete** it. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Manual scaling changes the `sku.capacity` property; in the portal use **Settings** → **Scaling** → **Manual Scale**, edit **Instance count**, and press **Save**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- CLI form: `az vmss scale --new-capacity 5 --name scaleSetName --resource-group resourceGroupName`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- PowerShell form: `Update-AzVmss -SkuCapacity 5 -ResourceGroupName resourceGroupName -VMScaleSetName scaleSetName`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Autoscale metric sources: the current scale set (host-based metrics, no agents), a storage account fed by the Azure diagnostics extension, an Azure Service Bus queue your app posts to, and Application Insights telemetry; host-based rules can be built with the portal, Azure PowerShell, Azure CLI, or an Azure template. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Host-based metrics available to rules: **Percentage CPU**, **Network In**, **Network Out**, **Disk Read Bytes**, **Disk Write Bytes**, **Disk Read Operations/Sec**, **Disk Write Operations/Sec**, **CPU Credits Remaining**, **CPU Credits Consumed**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Each rule aggregates its metric with one of: **Average**, **Minimum**, **Maximum**, **Total**, **Last**, **Count**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- The aggregated value is compared with your threshold using one of: **Greater than**, **Greater than or equal to**, **Less than**, **Less than or equal to**, **Equal to**, **Not equal to**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Scale actions when a rule fires: **Increase count by**, **Increase percent by**, **Increase count to**, **Decrease count by**, **Decrease percent by**, **Decrease count to**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- A single scale set supports at most 20 autoscale rules. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Scale sets reach up to 1,000 VM instances when built from standard marketplace images or from custom images stored in the Azure Compute Gallery (formerly Shared Image Gallery). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- The cap drops to 600 instances when the scale set is built from a managed image. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Turning on automatic instance repairs does not reduce that ceiling - it stays at 1,000 instances. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Production scale sets perform best on Azure managed disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))

## Compare and choose

- Flexible vs Uniform orchestration: choose Flexible for the unified VM experience, HA up to 1,000 VMs, stateful and quorum-based workloads, mixed VM types, Spot plus on-demand, or lifting Availability Set apps - and remember the mode is permanent. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Host metrics vs diagnostics extension vs Application Insights: use host metrics for zero-install CPU/memory/disk rules, the diagnostics extension for detailed in-guest counters such as **AverageReadTime** (disks) and **PercentIdleTime** (CPU), and Application Insights for app telemetry like response time, page load performance, and session counts. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Host-based vs in-guest metrics: host metrics need no agent; the Azure diagnostics extension is an agent that runs inside the VM, writes performance metrics to Azure storage, and requires storage accounts plus configured performance counters. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Fixed vs percentage vs target change: **Increase count by** / **Decrease count by** suit smaller scale sets, **Increase percent by** / **Decrease percent by** suit larger sets where a fixed change would barely move performance or cost, and **Increase count to** / **Decrease count to** create exactly as many as needed to reach a desired maximum or minimum. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Manual vs scheduled vs metric rules vs predictive AI: manual sets capacity on demand; schedule-based rules pre-provision for known peaks (start of workday, end of workday, monthly cycles, marketing events or holiday sales); metric rules react to sustained load; predictive AI reacts to discovered usage patterns. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Azure load balancer vs Application Gateway: pick **Azure load balancer** for basic layer-4 distribution, and **Azure Application Gateway** when you need layer-7 routing or TLS termination. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Marketplace image vs custom image vs managed image: marketplace images and custom images hosted in the Azure Compute Gallery allow up to 1,000 instances, while a managed image caps the scale set at 600. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Spot vs on-demand: flexible orchestration supports mixing Spot and on-demand VMs, letting cheaper capacity serve part of the workload. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Availability Zones vs fault domains: zone placement protects against data-center failure, while fault-domain isolation within a region suits quorum-based and stateful workloads. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))

## Gotchas

- Orchestration mode is fixed at creation, so a scale set created as Uniform cannot later be converted to Flexible or the reverse. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Autoscaling is inert until a virtual machine scaling profile defines the configuration of instances to add - configure that first. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- A scale set on its own is not a data-center failure solution; spread instances across Availability Zones if that matters. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- The 20-rule autoscale cap applies per scale set, so write a few meaningful rules rather than many narrow ones. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Choosing a managed image silently lowers your ceiling to 600 instances, well under the 1,000 available with other image sources. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/overview))
- Host-based metrics cover only the built-in list; anything more granular needs the Azure diagnostics extension plus storage accounts. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Percentage-based scale actions are a poor fit for small scale sets, where a fixed count change has a more visible effect on performance and cost. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Metric rules fire only after load stays at the threshold for the configured period; scheduled rules suit forecast demand, since the extra instances are already running and avoid a performance dip. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
- Credential policy is enforced at creation: a password shorter than 12 characters, or one matching fewer than three of the four character classes, fails validation. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- On Linux images choose **SSH public key** over a password, remembering you can reuse an existing key or have Azure generate the pair. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- The portal default **Scaling** mode is **Manual**, so the initial **Instance count** is only starting capacity - later changes come from autoscale rules or manual edits. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/flexible-virtual-machine-scale-sets-portal))
- Scale-in deliberately removes instances to cut cost, so keep a sensible minimum capacity rather than letting a rule strip the fleet during quiet periods. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machine-scale-sets/virtual-machine-scale-sets-autoscale-overview))
