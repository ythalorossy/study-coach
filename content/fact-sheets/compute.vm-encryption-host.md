# Configure encryption at host for Azure virtual machines

## Key concepts

- Encryption at host is a VM-level option that extends Azure Disk Storage server-side encryption (SSE): data written on the VM host is encrypted at rest and travels encrypted to the Storage service, so temp disks, disk caches and the compute-to-storage path are all protected. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview)) ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- SSE (encryption at rest) is always active for managed disks: OS and data disks are encrypted once persisted to the storage clusters, and it can use customer-managed keys through a disk encryption set, but it leaves temp disks and disk caches unencrypted. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Encryption at host is precisely the layer SSE misses: it adds temp disk encryption, cache encryption and encrypted data flows between compute and storage. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Temporary disks and ephemeral OS disks are always encrypted at rest with platform-managed keys when encryption at host is on; OS and data disk caches follow the encryption type of the disk itself (CMK disk → CMK-encrypted cache, platform-managed disk → platform-managed cache). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Azure Disk Encryption (ADE) encrypts OS and data disks from inside the guest OS using DM-Crypt on Linux and BitLocker on Windows; keys live in Azure Key Vault and can optionally be wrapped by a key encryption key (KEK). ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Confidential disk encryption binds the disk encryption keys to the VM's TPM so the protected content is readable only by that VM; TPM and guest state are always encrypted in attested code, and keys are released through a secure protocol that bypasses the hypervisor and host OS. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Confidential OS disk encryption covers the OS disk, confidential temp disk encryption is an opt-in, and on a confidential VM you can still use encryption at host for the remaining disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Encryption is one layer only: pair it with compute security recommendations and with restricting import/export access to managed disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))

## Settings and limits

- A subscription feature registration is mandatory before any VM or VMSS can use encryption at host: `Register-AzProviderFeature -FeatureName "EncryptionAtHost" -ProviderNamespace "Microsoft.Compute"` or `az feature register --name EncryptionAtHost --namespace Microsoft.Compute`, after `Set-AzContext -SubscriptionId "<yourSubIDHere>"` or `az account set --subscription "<yourSubIDHere>"`. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Confirm the state reads **Registered** with `Get-AzProviderFeature -FeatureName "EncryptionAtHost" -ProviderNamespace "Microsoft.Compute"` or `az feature show --name EncryptionAtHost --namespace Microsoft.Compute`; registration can take several minutes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- New VM with platform-managed keys: portal → **Virtual Machines** → **+ Create** → pick a region and a supported VM size → **Disks** pane → tick **Encryption at host** → complete the deployment; caches are then encrypted with platform-managed keys. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- New VM with customer-managed keys: same portal flow, but on the **Disks** pane open **Key management** and select one of your customer-managed keys before deploying. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- CMK resources must be created in this order: Azure Key Vault → key → Azure RBAC role assignment → disk encryption set → VM. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Key Vault requirements: soft delete and purge protection must both be enabled — soft delete retains a deleted key for a retention period (90 days by default) and purge protection blocks permanent deletion until that period lapses; both are mandatory for a vault used to encrypt managed disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Key creation: in the vault go to **Keys** → **Generate/Import**, leaving **Key Type** as **RSA** and **RSA Key Size** as **2048**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- RBAC: on the vault's **Access control (IAM)** tab add the **Key Vault Administrator**, **Owner**, or **Contributor** role so a disk encryption set can use the key. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Disk encryption set: **Disk Encryption Sets** → **+ Create** → resource group, name, and the same region as the vault; set **Encryption type** to **Encryption at-rest with a customer-managed key**, tick **Select Azure key vault and key**, choose the vault, key and key version, and optionally switch on **Auto key rotation** for automatic key rotation. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Once the disk encryption set is deployed, open it and select the displayed alert so the key vault is granted permissions to the set. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Placement rules: the disk encryption set, VM, disks and snapshots must all sit in the same region and subscription; the Key Vault may live in a different subscription but must share the DES region, and a vault in a different Microsoft Entra tenant is supported for managed disks. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Turning it off: deallocate the VM first — encryption at host cannot be disabled on a running VM — then VM → **Disks** → **Additional settings** → set **Encryption at host** to **No** → **Save**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Mutually exclusive with ADE: encryption at host cannot be enabled on a VM or VMSS that currently or ever had ADE enabled, and ADE cannot be enabled on disks that already have encryption at host. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Existing VM scale sets: encryption at host can be enabled on them, but only VMs created after that point are encrypted automatically — existing members must be deallocated and reallocated to become encrypted. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Ultra Disks and Premium SSD v2 only: a disk with a 512e sector size must have been created after 5/13/2023; if it is older, snapshot it and create a new disk from that snapshot. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Some older VM sizes are unsupported: check the supported-size list with the Azure PowerShell module or Azure CLI before deploying. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- The feature applies to both **Linux VMs** and **Windows VMs**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))

## Compare and choose

- Temp disk encryption: SSE no; encryption at host yes but only with platform-managed keys; ADE yes; confidential disk encryption yes but opt-in. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Encryption of caches: SSE no; encryption at host, ADE and confidential disk encryption all yes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Encrypted data flows between compute and storage: SSE no; encryption at host, ADE and confidential disk encryption yes. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Customer control of keys: SSE with a disk encryption set, encryption at host with a disk encryption set, ADE with a key encryption key, confidential disk encryption with a disk encryption set. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- HSM support: SSE, encryption at host and confidential disk encryption work with **Azure Key Vault Premium** and **Managed HSM**; ADE supports **Azure Key Vault Premium** only. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- CPU impact: SSE and encryption at host do not consume your VM's CPU; ADE and confidential disk encryption do. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Custom images: SSE, encryption at host and confidential disk encryption work with custom images; ADE does not work with custom Linux images. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Enhanced key protection: only confidential disk encryption offers it — SSE, encryption at host and ADE do not. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Microsoft Defender for Cloud disk encryption status: SSE reports **Unhealthy**, encryption at host and ADE report **Healthy**, confidential disk encryption is **Not applicable**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Defender for Cloud recommendations: one control flags VMs and VMSS that lack encryption at host and recognizes only that option; a second control checks that temporary disks, cache content and the in-transit path from compute to storage are protected but recognizes only ADE; two further controls cover Windows and Linux VMs and accept either ADE or EncryptionAtHost. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- Choosing between them: use encryption at host for new VMs — it delivers end-to-end encryption without guest-OS overhead and no dependency on ADE; choose confidential VM sizes with OS disk encryption when the workload needs TPM-bound confidential computing. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- ADE retirement: ADE retires on September 15, 2028; ADE-enabled workloads keep running but their encrypted disks fail to unlock after a VM reboot, so every ADE-enabled VM (backups included) must migrate to encryption at host before that date. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))

## Gotchas

- Feature registration is per subscription and takes minutes — you cannot tick **Encryption at host** for a VM or VMSS until the registration state shows **Registered**. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Do not mix up the two controls on the **Disks** pane: **Encryption at host** is the toggle that turns the option on, **Key management** is where you choose the customer-managed key for the caches; temp and ephemeral disks stay on platform-managed keys even with CMK. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- The encryption type of a disk encryption set is permanent: pick **Encryption at-rest with a customer-managed key** up front, because a later change means creating a brand-new disk encryption set. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Region and subscription mismatches are the classic deployment failure: the disk encryption set, VM, disks and snapshots must share region and subscription, while the vault may be cross-subscription but must be region-aligned with the set. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Soft delete and purge protection cannot be skipped when the vault is created for managed disk encryption — they are mandatory settings, not optional hardening. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Skipping the vault RBAC assignment, or ignoring the post-deployment alert on the disk encryption set, leaves the set without rights to the key and CMK-protected caches fail to work. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- The ADE conflict is historical, not just current: a VM that merely had ADE in the past can never have encryption at host switched on. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- Deallocate before disabling — encryption at host cannot be turned off on a running VM, and existing scale set members need deallocate plus reallocate to pick up the change. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal))
- SSE still protects data at rest on its own, yet Defender for Cloud flags SSE-only VMs as **Unhealthy** precisely because temp disks, caches and data flows remain unencrypted. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
- ADE's retirement failure mode is a reboot-time unlock failure rather than a runtime crash — plan the move to encryption at host (or confidential VM sizes with OS disk encryption) well ahead of September 15, 2028. ([Learn](https://learn.microsoft.com/en-us/azure/virtual-machines/disk-encryption-overview))
