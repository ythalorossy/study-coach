# Export a deployment as an Azure Resource Manager template or convert an Azure Resource Manager template to a Bicep file

## Key concepts

- Exporting turns resources that already exist into a reusable definition: from the portal you can generate either an ARM JSON template or a Bicep file, mainly to see the syntax and properties a deployment would need. The generated file usually needs adjustments before it can be used for a real deployment. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- The portal offers two export routes: **Export from resource group or resource** generates a brand-new template from live resources (a snapshot of their current state), while **Save from history** retrieves the exact template that was used for the deployment and returns ARM JSON only. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Decompiling is the JSON-to-Bicep conversion step: `az bicep decompile --file main.json` writes a **main.bicep** file beside the source JSON, and the Bicep CLI must already be installed to run it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Decompiled output and the source JSON are functionally equivalent rather than textually identical: a JSON to Bicep to JSON round trip can produce different syntax while deploying the same results, and the `build` command offers the same functional equivalence. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Visual Studio Code gives you shortcuts to the same goal: the **Decompile into Bicep** command, **Paste JSON as Bicep** (which runs the decompile automatically) and importing existing resources to create resource declarations directly. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Bicep Playground lets you compare an ARM template and its Bicep equivalent side by side: pick **Sample Template** for the built-in example, or **Decompile** to upload your own ARM JSON and view the Bicep file produced from it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- The portal is not the only export path: templates can also be exported with Azure CLI, Azure PowerShell, or the REST API endpoints for exporting from a resource group and from deployment history. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))

## Settings and limits

- **Include parameters** is the only toggle on the export screen and it is selected by default for both the resource-group export and the single-resource export; with it on, every template parameter is included in the generated template, and switching it off lets you author your own parameters instead. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- The exported template is created for a resource group that can hold at most 200 resources; going beyond that limit fails with the message `Export template is not supported for resource groups more than 200 resources`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- In the resource-group view you tick resources with the checkboxes (the box to the left of **Name** selects them all), and **Export template** in the top menu only becomes enabled once at least one resource is selected, whereas **Export template** in the left menu exports every resource in the group. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Once generated, choose **ARM Template** to display the result so that it can be downloaded or deployed directly. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Single-resource export: open the resource from its resource group and choose **Export template** in the left pane; the resulting template contains only that one resource and still offers the default-on **Include parameters** checkbox. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Deployment-history export: open the resource group, follow the **Deployments** link, select a deployment in the history list, then select **Template** to see the exact template used for that deployment, ready for download. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- The decompile command writes `main.bicep` into the same directory as `main.json`; if a `main.bicep` already exists there, you must add the `--force` switch to overwrite it. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- If you do not use Azure CLI, drop the `az` prefix: the equivalent standalone command is `bicep decompile --file main.json`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Exporting a group and converting it in one flow: `az group export --name "your_resource_group_name" > main.json` followed by `az bicep decompile --file main.json`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Templates generated from a resource group or resource are built from the published schemas for each resource type; when the schema is behind the newest API version you must edit the exported template to use the API version you actually need. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Decompilation maps JSON constructs onto Bicep ones: `allowedValues` becomes an `@allowed` decorator list, `metadata.description` becomes `@description`, and `defaultValue` becomes the parameter default, for example `param storageAccountType string = 'Standard_LRS'` with allowed values `Standard_LRS`, `Standard_GRS`, `Standard_ZRS` and `Premium_LRS`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Bicep identifiers, parameter names included, may only contain letters, digits and underscores, so a JSON parameter named `Security.Authentication.AAD.Tenant` comes back as `Security_Authentication_AAD_Tenant` after decompiling. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- In VS Code you can rename a symbol throughout the file by right-clicking it and choosing **Rename symbol**, or with the **F2** hotkey; generated names such as `storageAccountName_var` are usually changed to something meaningful like `uniqueStorageName`. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))

## Compare and choose

- Template origin decides the quality: a resource-group or resource export is autogenerated and normally needs improving before you deploy it, while a history export is an exact copy of the template its author wrote and can be redeployed with no changes at all. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Drift handling differs: the resource-group export is a snapshot of the resources' current state and captures manual changes made after the original deployment, whereas the history export shows only the state at deployment time and excludes those later manual edits. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Selection scope differs: with a resource-group export you choose exactly which resources to include, but a history export always pulls in every resource of that one deployment and you cannot take a subset or add resources deployed at a different time. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Property density differs: a resource-group export includes all properties of the resources, including ones you would not normally set during a deployment and may want to clean up, while a history export contains only the properties the deployment needed and is therefore sparser and easier to read. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Parameterisation differs: a resource-group export usually lacks the parameters you need for reuse and hard-codes most property values, so you must add parameters yourself (or clear **Include parameters**), while a history export already carries the parameters that make redeploying into other environments easy. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Choose the resource-group or resource route when you need changes made after the original deployment captured, when you want to pick which resources are exported, or when the resources were never created from a template in the first place. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Choose the history route when you want an easy-to-reuse template and do not need the changes that were made after the original deployment. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- For Bicep output, exporting Bicep directly from the portal is the shortest path when you have no JSON yet, whereas decompiling is the route for a JSON template you already own, and the resulting file still needs revising to follow best practices. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- For anything production-grade, hand-writing a Bicep file, an ARM template or terraform is safer than exporting existing resources, because export is not guaranteed to succeed and is explicitly not a dependable way to produce usable templates. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))

## Gotchas

- Export can fail and is not a reliable path from pre-existing resources to production-ready templates; the guidance is to write the definition from scratch instead. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Some password parameters may be missing from an exported template, so you must consult the template reference and add those parameters manually before you can deploy the resources. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Azure Data Factory resources are not supported by the export template feature; use the copy or clone data factory capability for those instead. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Resources created through the classic deployment model must first be migrated to the Resource Manager deployment model, otherwise they cannot be exported. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- If the export warns that a resource type was not exported, you can still find its properties in the template reference or through the Azure REST API for that resource type. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- There is no guaranteed mapping from JSON ARM templates to Bicep: decompiling may emit warnings or errors that you have to fix, and it can fail outright when an accurate conversion is not possible, so report broken or inaccurate conversions as an issue. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Because periods in parameter names become underscores after decompiling, remember to update every reference to those parameters in your templates and in your parameter files. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- Decompiled files contain machine-generated variable and resource symbolic names such as `storageAccountName_var` or `storageAccountName`, so review and rename them before relying on the file. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/bicep/decompile))
- A history export only ever hands you ARM JSON, never a Bicep file, so getting Bicep from a deployment history means an extra decompile step on top of the export. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
- Because the generated template relies on published schemas that can lag the resource provider, always check that the API version and the properties you need are present before you deploy the exported file. ([Learn](https://learn.microsoft.com/en-us/azure/azure-resource-manager/templates/export-template-portal))
